# 管理台菜单

管理台（`server/main/companion-console`）默认只显示网页对话需要的页面。硬件冻结期间，设备、固件这些页面从菜单和路由里隐藏，代码和后端接口都保留，用一个构建开关可以放回来。

## 默认的八个菜单项

| 菜单项 | 包含的页面 | 地址 |
|---|---|---|
| 概览 | 网页对话的运营概览 | `/dashboard` |
| 网页端 | 以当前管理台账号直接使用网页端，也可以在新窗口打开 | `/web`（旧的 `/playground` 跳到这里） |
| 预设角色 | 用户在网页端可以选的角色 | `/admin/templates` |
| 模型与声音 | 模型、声音 | `/admin/models`、`/voices` |
| 用户 | 用户、邀请码 | `/admin/users`、`/admin/invite-codes` |
| 数据 | 留存与体验、对话用量 | `/admin/analytics`、`/admin/usage` |
| 安全事件 | 安全事件 | `/admin/safety-events` |
| 设置 | 系统设置、参数、审计日志 | `/admin/system-settings`、`/admin/system-params`、`/admin/audit` |

一个菜单项包含几个页面时，页面上方有一条切换条。每个页面的地址和权限都没有变，旧的链接和书签继续有效。

没有管理权限的账号只看到“概览”、“网页端”和“声音管理”。这时“概览”只提示去网页端聊天，不请求任何管理数据。

## 概览

默认的概览显示今天聊过的用户数、今天的对话轮数、近 7 天新用户数、最近一天的首字耗时中位数，以及最近 7 天每天的用量。数据来自“对话用量”和“留存与体验”已有的两个接口，没有新增后端接口。

“今天”按浏览器的本地日期取。管理员所在时区和服务器不一致时，“今天”这两个数会对不上，以“数据”里的按天表格为准。

原来的概览只有设备、角色和订阅，放回 `hardware` 分组后会换回原来的那一页。

## 默认隐藏的页面

| 分组 | 页面 |
|---|---|
| `hardware` | 我的设备、设备详情、设备运营、固件管理、屏幕编排，以及原来的设备概览 |
| `workbench` | 陪伴角色、编辑陪伴角色、记忆 |
| `billing` | 订阅、套餐与订阅 |
| `capabilities` | 能力中心 |

隐藏的页面不注册路由，直接输入地址会显示“页面不存在”。这只是管理台前端不再提供入口，后端接口和权限检查没有改动，不能把隐藏当成访问控制。

## 把隐藏的页面放回来

构建或启动管理台时设置 `VITE_CONSOLE_FEATURES`，写分组名，多个用逗号分隔，或者写 `all`：

```bash
VITE_CONSOLE_FEATURES=hardware,workbench npm run dev
```

- 这是构建时的设置，改了以后要重新构建或重启开发服务。
- 只要放回了任何一个分组，菜单就会恢复按“工作台 / AI 能力 / 平台管理”分组显示，因为菜单项变多了。
- `hardware` 的设备详情会链接到陪伴角色，要和 `workbench` 一起开。
- 能力中心里“去设备页绑定”的链接指向设备页，单独开 `capabilities` 时这个链接打不开。

## 改菜单时看哪里

- 页面、分组、合并关系都定义在 `src/app/navigation.tsx` 的 `consoleRoutes`。数组顺序就是菜单顺序，同一个 `section` 里的顺序就是切换条的顺序。
- 路由表由 `src/app/router.tsx` 的 `buildConsoleRoutes` 按启用的分组生成。
- 切换条在 `src/app/AppShell.tsx` 里渲染。
