# 对话的连续性

用户和角色之间聊过什么，不应该随着一次连接结束而消失。本文记录网页对话怎样在令牌过期、断线、刷新页面和隔天再来之后接上之前的内容。

## 会话和对话记录是两件事

会话是一次连接。manager-api 为它签发 15 分钟有效的运行时令牌，单个会话最多 100 轮，连接断开后会话就结束。

对话记录按“用户 + 角色”保存在 `ai_conversation_turn` 表里，每一轮一行，只存文字。它不属于任何一个会话。

新会话建立时，`zixuan-server` 向 manager-api 取这个用户和这个角色最近 20 轮对话，作为本次会话的起始上下文。这些轮次只当上下文用，不计入本次会话的轮数上限，也不会重复写回。

取不到对话记录时会话照常开始，不会因此连不上。

## 带给模型的上下文

每一轮请求里，模型看到的是：系统提示词、之前的对话（先是从对话记录里取回的，再是本次会话里新产生的）、用户当前这句话。

之前的对话最多带 20 轮，总字数不超过 8000。超出时保留最近的。更早的内容由记忆模块负责。

失败的一轮不会留下半截对话。

## 哪些对话会被记录

只有登录用户的会话计入对话记录，包括手机号登录和从管理台进入。

通过 API Key 创建的会话不计入。一个 API Key 背后可能是很多不同的终端用户，把他们的对话合并到一条记录里既不正确，也会互相泄露。这类会话沿用原来按会话保存在 Redis 里的历史。

运行时配置里的 `historyThread` 表示这个会话是否计入对话记录，由 manager-api 在创建会话时决定。

## 用户能做什么

- `GET /api/v1/conversations/threads/{agentId}` 读取自己和一个角色最近的对话，网页端进入时用它显示之前聊过的内容。
- `DELETE /api/v1/conversations/threads/{agentId}` 删除自己和一个角色的全部对话记录。

这两个接口只对登录用户开放，并且只能访问自己的角色。

## 网页端怎样做到无感

网页端选好角色后自动连接，不需要手动点连接。

- 令牌快过期时服务端会提前通知。当前没有在说话就立刻换一个新会话，正在说话就等这一轮结束再换。
- 单个会话接近 100 轮的上限时，在两轮之间换一个新会话。
- 连接意外断开时自动重连，间隔从 1 秒开始翻倍，最长 15 秒。连续失败 6 次后停下来，显示“重新连接”按钮。
- 重连期间仍然可以输入，发出的话会在连上之后补发。
- 用户自己点了“断开”时不自动重连，直到再点“连接”。

换会话时先建立新连接，再关闭旧连接。旧连接迟到的事件一律忽略，所以不会出现重复的回复或错误的状态。

## 尚未处理

- 对话记录没有保留期限，只能由用户主动删除。
- 记录是明文保存的。
- 语音没有保存，只保存识别出的文字和回复的文字。
