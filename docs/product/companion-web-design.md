# 网页端的产品和界面设计

这份文档记录网页端（`server/main/companion-web`）重做界面时的判断：它是一个什么应用、保留和去掉了哪些功能、页面怎么组织、样子怎么定、图片是怎么来的。

**其中的产品判断是草案。** 用户画像、角色形象和文案没有用户数据支持，内测时要看实际使用再调整。

## 它是什么应用

一个和陪伴角色一对一聊天的应用。用户选一个有固定性格的角色，打字或者直接开口说，角色记得之前聊过的事。

前期的用户是年轻的成年人。他们每天用微信、小红书这类应用，对“左边是对方、右边是自己、底下是输入框”的聊天界面不需要学习。所以界面的原则是：

- **像聊天软件，不像工具。** 进来就是对话，没有需要先配置的东西。连接、会话、模型这些词不出现在界面上。
- **角色是主角。** 每个角色有自己的形象，出现在选角色、角色列表、每句回复旁边和语音通话里。
- **不花哨。** 一种底色、一种强调色，没有渐变、徽章、等级、签到这类东西。
- **语音是它和普通聊天机器人的区别。** 开口说话要和打字一样近，并且有一个专门的通话界面。

## 功能

### 保留并且重新安排的

| 功能 | 以前 | 现在 |
|---|---|---|
| 切换角色 | 顶部的下拉框 | 左边的角色列表（手机上点头像从左边滑出） |
| 添加角色 | 下拉框的最后一项 | 角色列表底部的“添加角色” |
| 换声音 | 顶部一直显示的下拉框 | 收进“设置”，很少用 |
| 连接状态 | “已连接 / 处理中”的状态牌 | 名字下面的一行小字：在线、正在输入…、通话中、正在重新连接 |
| 语音 | 输入框旁的麦克风开关，状态是一行字 | 点麦克风进入通话界面 |
| 重听回复 | 回复气泡里的按钮 | 回复下面的小按钮 |
| 清空记录、协议、退出、注销 | “账号与数据” | “设置” |

### 去掉的

- **“断开 / 连接”按钮。** 连接是自动的，用户不需要管。只有连续重连失败后才出现“重新连接”。

### 新加的

- **“正在输入”的气泡。** 用户说完到回复开始出现之间有一两秒，以前这段时间页面没有变化。
- **开场的几句话。** 还没和这个角色说过话时，输入框上方给出三句可以直接点的话，每个预设角色有自己的三句。用户说过一句之后不再出现。
- **关掉自动朗读。** 顶部的喇叭按钮。在教室、办公室、宿舍这些不方便出声的地方，回复只显示文字，想听时点“重听”。这个选择记在浏览器里。语音通话不受它影响。
- **图片预览。** 选好的图片在发送前显示缩略图，可以移除。以前选完只是输入框的提示文字变了。图片超过 6MB 时会提示，以前是没有反应。
- **深色模式。** 跟随系统设置。
- **加载失败可以重试。** 角色列表加载失败时显示原因和“重试”。

### 这次没有做的

- 角色的删除和改名。
- 消息的时间。历史记录接口有时间，页面没有显示。
- 试听声音。
- 自己选的声音只在这次打开页面期间有效，刷新后回到角色默认的声音。
- 自动朗读关掉时，服务端仍然会合成语音（这样才能“重听”）。要省这部分成本，需要在创建会话时不要求语音输出，这次没有改。

## 页面

一共四个画面，加一个设置面板。

**登录。** 上面（宽屏上是左边）是三个角色的合影和一句话，下面（右边）是手机号登录的表单。

**选角色。** 新账号登录后先选一个。每个角色是一张卡片：形象、名字、一句介绍。已有角色的用户从角色列表进来时，已经有的角色显示“已添加”。

**对话。** 应用的主体。

- 宽屏（900px 以上）：左边是角色列表，右边是对话，对话内容的行宽不超过 760px。
- 手机：只有对话。点左上角的头像，角色列表从左边滑出。
- 顶部：头像、名字、状态，右边是喇叭（自动朗读）和设置。
- 中间：消息。角色的话在左，带头像；自己的话在右，用强调色。同一个人连着说的几句只在第一句旁边放头像。
- 底部：输入栏。左边是添加图片；没有内容时右边是麦克风，有内容时变成发送。最下面一行小字说明角色是 AI。
- 错误、断线、休息提醒、今天次数用完，都以提示条的形式出现在消息上方。

**语音通话。** 点麦克风后盖在消息上面，只有大头像、当前状态、最近一句话和结束按钮。

- 状态有四种：直接说话就可以、在听你说、在想、在说（可以随时打断）。在听和在说的时候头像外面有一圈扩散的光环。
- 最近一句话是用户正在说的，或者角色刚说的。
- 说过的话照常记在对话里，结束通话后都能看到。
- 通话时换角色会先结束通话。

**设置。** 手机上从底部升起，宽屏上居中。分两组：当前角色（声音、清空对话记录）和账号（隐私政策、用户协议、退出登录、注销账号）。

## 样子

颜色、圆角、间距都定义在 `app/globals.css` 开头的变量里，深色模式只换变量。

- **底色**是暖白的纸色（`#f6f1e8`），和角色图片的背景接近。深色模式是暖黑（`#181614`）。
- **强调色**只有一种紫色（`#6451c4`），用在自己的消息、主要按钮和选中的角色上。产品叫“紫萱”，所以选了紫色。
- **字体**用系统自带的中文字体，不加载网络字体。
- **动效**很少：新消息轻轻浮现，输入中的三个点，通话时头像的呼吸和光环。用户在系统里选了“减少动态效果”时全部关掉。
- 输入控件字号不小于 16px、可点的东西不小于 44px 的约定没有变，见 `docs/web-mobile.md`。

## 角色形象

三个预设角色做成了羊毛毡玩偶：紫萱是浅紫色的垂耳兔，阿澈是灰蓝色的猫，小满是蜜黄色的小熊。

选玩偶而不是人像，有三个原因：和将来的毛绒硬件是同一个形象；角色的关系定位是朋友，玩偶不会让人往恋爱方向想；三个放在一起风格统一，不用担心画得像不像某个人。

**这也是草案。** 动物、颜色和神态是为了让界面成型而定的，可以整体替换。

### 图片在哪里

| 文件 | 用处 |
|---|---|
| `public/roles/<角色>.jpg` | 头像，512px |
| `public/roles/<角色>-motion.webp` | 语音通话时会眨眼的头像，400px，循环播放 |
| `public/art/together.jpg` | 登录页的合影 |
| `app/icon.png`、`app/apple-icon.png` | 浏览器标签和添加到主屏幕的图标 |

角色和图片的对应关系写在 `lib/roles.ts`，按角色名字匹配，同时还有列表里的短介绍和开场的三句话。服务端目前不保存头像。名字对不上的角色（管理台里新加的预设、从管理台进来的角色）显示名字的第一个字和一个底色。

### 图片是怎么生成的

都是用 `gpt-image-2.6-flare` 生成的，通过 mowa-media 的图像接口。

- **头像**：先用文字生成紫萱，再把紫萱的图作为参考，用改图接口生成另外两个，这样三张的材质、光线、构图和背景一致。
- **合影**：把三张头像一起作为参考图生成。
- **会动的头像**：`gpt-image-2.6-flare` 的文生图接口加上 `output_format: "gif"` 可以直接返回动图，9 帧，循环。实际用下来有三点要知道：
  - 只有文生图接口支持，改图接口会返回“GIF output is not enabled for this request”。所以动图不能从已有的头像改出来，只能用文字重新描述，形象和静态头像很接近但不完全一样。
  - 同样的请求有时成功有时被同一句话拒绝，需要重试。
  - 返回的 GIF 是 1024px、5MB 左右。放进网页前缩到 400px 转成 WebP，每个 50 到 70KB。第一帧的停留时间加长到两秒多，看起来是安静地待着、偶尔眨一下眼，而不是一直在动。

要换一个角色的形象：替换 `public/roles/` 里对应的文件。要给新的预设角色加形象：放好图片，在 `lib/roles.ts` 里加一项。

## 验证情况

已经验证的：

- 在本机浏览器里用 375×812 和 1280×800 两种尺寸、浅色和深色，看过登录、对话、角色列表、添加角色、设置。
- 真实发了文字消息，看到“正在输入”、回复和“重听”。
- 自动化测试覆盖了切换和添加角色、开场的话、正在输入、自动朗读的开关、语音通话的进入和结束。

还没有验证的：

- **语音通话没有真的拨通过。** 验证用的浏览器不提供麦克风。通话界面的样子是单独渲染出来检查的，流程由自动化测试覆盖，其中麦克风和声卡是模拟的。需要在普通浏览器里实际说几句。
- 手机真机，原因见 `docs/web-mobile.md`。
- 新账号第一次选角色的真实流程（现有测试账号已经有三个角色）。
