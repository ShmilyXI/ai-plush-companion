# 网页端的产品和界面设计

这份文档记录网页端（`server/main/companion-web`）的设计判断：它是一个什么应用、页面怎么组织、角色怎样出现在页面上、样子怎么定。

**其中的产品判断是草案。** 用户画像、角色形象和文案没有用户数据支持，内测时要看实际使用再调整。

## 它是什么应用

一个和陪伴角色对话的应用。主体是一页正常的对话；点一下就能进入不用手的语音通话，这时角色以一个会动的 3D 形象出现，通话里说的话照常记在对话里。

前期的用户是年轻的成年人。界面的原则：

- **对话页是大家熟悉的样子。** 角色的话在左，自己的话在右，底部是输入栏。
- **通话时角色看得见。** 它有一个实时渲染的形象，会听、会想、会开口。平时打字聊天时页面上只有对话，不放形象。
- **语音和打字在同一页。** 开始通话不会跳到另一个页面，只是底部的输入栏换成声浪，对话照常往下走。
- **界面本身只有黑白灰。** 颜色来自角色，换一个角色，页面的色调跟着变。

## 页面

**主页面**从上到下：

- **顶栏**：左边是打开侧栏的按钮，然后是角色的名字和一行状态（在线、在听你说、在想、在说话、通话中、正在重新连接）；右边是放大或缩小角色的按钮和自动朗读的开关。
- **角色**：一直在页面上。它有两种样子，用的是同一个形象，在两者之间切换是一个连续的缩放动作。
  - 缩小（平时）：一只 88 像素左右的桌宠，待在对话区右下角、输入栏（有开场的话时是开场的话）上方。对话底部留出它的位置，滚到底时最新的消息不会被它挡住。可以随意拖动，拖到哪里记在浏览器里。打字时它也留在原处。
  - 放大：点一下桌宠，它站到对话上方（宽屏上在对话右边），占屏幕高度的三分之一左右。没有边框和底色，身后只有一团很淡的光。再点一下它、点右上角的缩小，或者自己往回翻对话，它就缩回角落。
  - 缩在角落里时它照样会眨眼、呼吸、开口说话时对口型；在听和在想时只摆一个歪头的姿势，不逐帧计算，省电。
- **对话**：角色的话在左边的白色气泡里，带头像；自己的话在右边的浅色气泡里。气泡没有边框。通话里语音识别出的话和打字发的话是一样的消息。
- **回复的操作**：长按角色的回复（电脑上右键，键盘上回车），页面变暗变模糊，这条回复浮起来，旁边弹出“复制”和“朗读”。点一下什么都不做，免得滚动时误触。菜单放在页面最上层，不会被后面的消息盖住。气泡里的字不能选中，否则手机会先弹出自己的选字菜单。
- **开场的话**：还没和这个角色说过话时，输入栏上方有三句可以直接点的话。
- **输入栏**：左边加图片，中间打字，写了内容才出现发送，最右边是开始语音通话。

**通话时**角色是主角，页面不跳转：

- 角色自己放大走到前面来，挂断后缩回角落。通话中可以自己把它缩小；这时翻对话它不会让开。
- 角色身后的光圈跟着状态变：在听时亮起一圈，在想时慢慢明暗，开口时跟着声音一起一伏。
- 角色下面有字幕：用户在说时显示识别出来的话，角色在说时显示正在念的那一句。语音是一句一句合成的，每句带着它的文字，播到哪句就显示哪句（`lib/playback.ts` 的 `current()`），不会跑在声音前面。
- 前面的对话变淡，只有最近两条看得清。
- 底部的输入栏换成一条通话栏：中间是一颗随声音涨落的光，左边是关麦克风（不挂断），右边是结束通话，上面一行小字写着现在的状态。
- 页面底部的光变亮。

通话中直接说话，说完停顿一下就算一句；角色在说的时候可以直接开口打断。换角色会先结束通话。怎样判断“在说话”、怎样排除噪声、打断怎么做，见 `docs/web-call-audio.md`。

**陪伴模式**：通话中双方都安静了一阵子（第一次 30 秒，之后 1 分钟、2 分钟），角色会想一想要不要主动找个话题。有自然的切入点才开口，没有就继续安静陪着；用户连着三次没接话就不再找，等用户开口后重新算。设置页“通话”一栏可以关掉，默认打开。细节同样在 `docs/web-call-audio.md`。

结束通话只是不再收音：连接保留，正在读的回复停下来，接着打字不用等。

**其他画面**：

- 登录：三个角色的形象和手机号表单。
- 选角色：每个角色一张卡片。
- 侧栏：从左边滑出。点左上角的按钮打开；在触摸屏上，手指在页面上往右滑也能打开，往左滑收起。竖着翻对话和在开场的话那一行横向滑动不会触发。顶上的标题是 Mowa。从上到下三块：
  - 一排角色的头像和名字，横着排，多了可以左右滑。点头像换过去，最后一个是“添加”。
  - 当前角色的头像、名字和“角色设置”按钮，下面是和它聊过的日子，从最近一天往前（今天、昨天、11月20日……），每天带第一句话。每个角色只有一段一直延续的对话，所以这里列的是哪几天聊过，不是很多段对话。点一天，对话往前读到那天并滚到那天开头。
  - 自己的账号：头像、昵称（没设昵称时是中间四位打码的手机号）和“内测版 · 角色 4/5”这样的套餐一行。点进去是个人中心。每次打开侧栏都重新读一遍，个人中心里刚改的昵称和头像马上就能看到。
- 对话：换了一天的地方有一个日期。翻到最上面附近会自动读更早的一页，每页 30 轮。
- 个人中心：单独的一页，左上角返回。从上到下是账号卡片（头像、昵称或打码的手机号、套餐、角色用了几个、已陪伴几天）、外观（主题）、通话（主动找话题）、关于（协议）、退出登录和注销账号。某个角色的东西都在角色设置里，不放在这里。
  - 点账号卡片进“编辑资料”：可以上传、更换或移除头像，改昵称。昵称最多 20 个字（一个表情算一个字），不填就显示打码的手机号。选的图片在浏览器里裁成居中的正方形、缩到 256 像素、转成 JPEG，先显示预览，点保存才上传；只发改了的项。服务端（`POST /app/v1/auth/profile`，存在 `app_user_profile` 表）只收 JPEG、PNG、WebP 的 data URL，并核对文件头；注销账号时一起删除。从管理台过来的会话没有这一项。

## 角色设置和新建角色

每个角色都可以由用户自己调。入口在侧栏里当前角色名字旁边的“角色设置”按钮。角色设置是单独的一页：窄屏上从上到下一列，宽屏上左边是角色的形象，右边是其余的设置，右上角保存，左上角返回。

可以改的：

- **形象**：预设角色有为它画的形象，这里只展示，不能换。从空白开始的角色在兔子、猫、小熊里三选一，上面是会动的预览；再从六种颜色里选一种，它决定通话时页面的光。（启用 3D 角色时，颜色同时是角色身体的颜色。）
- **名字**，以及**它怎么称呼你**。
- **性格**：一段自己写的话，下面有几个可以直接点的词，点一下加进去，再点一下去掉。
- **声音**。
- **高级**：完整的提示词，默认收起。从预设创建的角色可以恢复成预设的原样。
- 页面最下面一张卡片放两个危险操作，样式和个人中心的退出登录、注销一样：
  - **清空和它的对话记录**，要再确认一次。清空后它也不再记得之前聊过什么。
  - **删除这个角色**，要再确认一次，和它的对话记录一起删掉。
- 下拉框和「高级」用同一个向下箭头，展开时箭头朝上。

保存后立刻生效：正在和这个角色聊的话，会换一个新会话用上新的设置。

**新建角色**有两种起点：选一个预设，或者“从空白开始”。空白角色建好后直接打开它的设置，让用户起名字、写性格。它的提示词只有所有角色都守的几条约定（朋友关系、简短口语、不冒充真人）。

几条边界：

- **关系固定是朋友。** 后端的角色有一个“关系”字段可以设成恋人，网页端不提供这一项，保存时也不会把它改掉。
- **平台的内容安全守则改不掉。** 它由对话服务在每次对话时附加在提示词最后，不存在角色的设置里，用户把提示词改成什么都不影响它，见 `docs/content-safety.md`。
- **角色数量有上限**，由套餐决定，基础套餐是 3 个。满了要先删一个才能新建。
- **形象记在浏览器里。** 只有从空白开始的角色能选形象。服务端目前没有存形象的地方，所以换一台设备会回到默认的样子：蜜黄色的小熊。
- **它记得的事**可以逐条删除、全部忘掉，也可以自己写一条让它记住。这部分的增删立刻生效，不用点保存。记忆是怎么来的见 `docs/conversation-memory.md`。

实现上要注意：后端保存角色只是存了一个新版本，对话用的是“生效的版本”。网页端保存时带上 `activate=true`，后端在保存后把最新版本设为生效。管理台保存角色不带这个参数，仍然是先保存、再自己选版本激活。

## 角色怎样出现在页面上

角色的画法由环境变量 `NEXT_PUBLIC_CHARACTER_STYLE` 决定（`components/RoleCharacter.tsx`）：

| 值 | 画法 |
|---|---|
| 不设（默认） | 每个角色用自己的 2D 图；有为它定制的 Live2D 模型的角色用 Live2D |
| `live2d` | 所有角色都用 Live2D，没有定制模型的用官方示例模型 |
| `2d` | 所有角色都用自己的 2D 图 |
| `none` | 不显示会动的角色，通话时只有底部的通话栏 |
| `3d` | 用 three.js 搭的角色 |

默认不用 Live2D 示例模型，是因为它们和角色的样子对不上：以前通话时年糕会变成示例模型 Mao、苏念会变成 Hiyori，和头像、选角色时看到的完全是两个人。定制的模型在 `lib/roles.ts` 的 `LIVE2D_MODELS` 里加一项并标上 `custom: true`、把角色指过去，那个角色就自动用 Live2D。

### Live2D 模型（定制模型或 `live2d`）

在 `components/Live2DCharacter.tsx`，用 [pixi-live2d-display](https://github.com/guansss/pixi-live2d-display) 0.4（基于 PixiJS 6）显示。模型自己会播待机动作、眨眼、呼吸，这里在上面再叠三样：

| 状态 | 动作 |
|---|---|
| 平时 | 模型自己的待机动作 |
| 在听用户说 | 歪头，看着用户 |
| 在想 | 头转向一边，眼睛往上看 |
| 在说话 | 嘴按自己声音的音量开合，轻轻点头；开始说一段话时偶尔做一个小动作 |
| 连接断开 | 低头 |

控制嘴的参数按模型文件里写的“LipSync”组来找，没写的用 `ParamMouthOpenY`。显示的是头到腰的上半身，窄的地方按宽度缩放。

**现在用的是 Live2D 官方的示例模型**，不是为我们的角色做的：紫萱用 Hiyori，小满用 Mao，阿澈用 Mark，其他角色按名字从三个里选一个。角色设置里可以换模型。对应关系在 `lib/roles.ts` 的 `LIVE2D_MODELS`，以后有了定制模型在这里加一项就行。头像、登录页和选角色卡片仍然是之前的动物图片，和 Live2D 模型对不上。

**模型和运行库不在仓库里。** 它们属于 Live2D Inc.，仓库是公开的，放进去就成了再分发。每个要运行网页端的环境先在 `companion-web` 目录下执行：

```bash
python3 scripts/fetch-live2d.py --accept-license
```

它会下载运行库 `live2dcubismcore.min.js`（约 200KB，来自 cubism.live2d.com）和三个示例模型（共约 10MB，来自 Live2D 官方的 GitHub 仓库 CubismWebSamples），放到 `public/live2d/`，这个目录已经在 `.gitignore` 里。`--accept-license` 表示接受 Live2D 的授权协议：运行库是 Live2D Proprietary Software License，示例模型是 Live2D Free Material License。年销售额 1000 万日元以上的企业对外发布时需要和 Live2D 另行签约。部署时这一步也要做。

文件没下载时，角色的位置显示静态的图片，通话照常。运行库也可以通过 `NEXT_PUBLIC_LIVE2D_CORE_URL` 指到别的地址。

**加载速度。** 一个角色要下载的东西不小：运行库约 200KB，显示模型的两个库（开发模式下没有压缩，约 2.6MB，正式构建后会小很多，具体多少没有测），模型约 1MB，贴图 0.2 到 3MB。以前要等用户点了通话才开始下载，经公网域名访问时要等好几秒甚至更久。现在做了三件事：

- 聊天页打开后，浏览器空闲时就把当前角色要用的东西提前下载好（`preloadLive2D`）。点通话时直接从缓存里拿，本机测得角色 40 毫秒内出来。
- 下载脚本把贴图无损转成 WebP，大小约减半（Mao 3MB 变成 1.6MB，Hiyori 两张共 4.1MB 变成 1.9MB），画质不变。需要装 Pillow，没装时照常用 PNG。网页用的是脚本生成的 `<模型名>.web.model3.json`，原始文件不动。
- `/live2d/` 下的文件让浏览器缓存一周，再次通话不用重新下载，也不用每次都问一遍服务器。

还慢的情况：打开页面后马上就点通话，提前下载还没完成。另外经公网访问开发服务器（`npm run dev`）时，库文件没有压缩，比正式构建（`npm run build` 后 `npm run start`）大得多；对外访问建议用正式构建。`.moc3` 文件 Next 不会压缩，前面有 nginx 这类代理时可以给它开 gzip。

### 图片做的 2D 角色（默认）

在 `components/Puppet.tsx`。每种动物有三张图：

- 一张正面的全身像（睁眼、闭嘴），透明底。
- 一张“闭眼”和一张“张嘴”，都是只有眼睛或嘴那一小块的透明图，叠在全身像上。

眨眼和说话就是让这两块补丁显示或隐藏；呼吸、歪头、晃动、跟着声音颠，是对整张图做位移和旋转。

| 状态 | 动作 |
|---|---|
| 平时 | 呼吸，轻轻左右晃，隔几秒眨一次眼 |
| 在听用户说 | 歪头，往前凑 |
| 在想 | 头歪向另一边，慢慢晃 |
| 在说话 | 嘴按自己声音的音量开合，身体只轻轻晃，不跟着声音上下颠 |
| 连接断开 | 闭眼，整体变淡 |

说话时的音量是从播放语音的 `AudioContext` 上实时读出来的（`lib/playback.ts` 的 `level()`），所以嘴的开合和听到的声音是对上的。通话栏里的那颗光用的是同一个音量。

这不是 Live2D。Live2D 需要在它的编辑器里把角色拆成几十个部件并绑定好，运行时还要用它自己的核心库，这个库有单独的授权协议；模型和授权都要有人去做和确认。现在的做法只有三张图，能做到眨眼、对口型和整体的摆动，做不到头发飘动、转头、细致的表情这些。以后有了请人做的 Live2D 模型，替换 `RoleCharacter` 里用的组件就可以，页面其他部分不用改。

### 用代码搭的 3D 角色（`3d`）

在 `components/Character.tsx`，用 three.js 实时渲染，头、身体、耳朵、眼睛、嘴都是基本形状搭出来的，会眨眼、转头、对口型。它比较朴素，代码完整保留。

把环境变量 `NEXT_PUBLIC_CHARACTER_STYLE` 设成 `3d` 再启动，就换回 3D 角色。这时角色设置里选的颜色同时是角色身体的颜色。3D 库只在用到时才加载。

两种画法接收的东西一样：角色、状态、音量。

## 样子

颜色都定义在 `app/globals.css` 开头的变量里，深色模式只换变量。

主题有三种，在设置页里选：跟随系统（默认）、浅色、深色。选了浅色或深色时，在 `<html>` 上写一个 `data-theme` 属性，样式按它来；跟随系统时不写。选择记在浏览器里，页面最前面有一小段脚本在第一次绘制之前把它写上，所以选了深色的人打开时不会先闪一下浅色。实现在 `lib/theme.ts`。浏览器地址栏的颜色仍然只跟随系统，不跟随这里的选择。

- **底色**是很浅的灰白。
- **底部的光**：页面底部漫上来一层很淡的角色颜色，通话时变亮。每个角色三种颜色，写在 `lib/roles.ts`：紫萱是紫和粉，阿澈是蓝和青，小满是黄和橙。声浪和头像的底也用这三种颜色。
- **控件**：顶栏的按钮、输入栏和通话栏都是毛玻璃质感：半透明的底，透出背后模糊的内容，边缘有一道很细的亮线，参考的是 iOS 的做法。主要的按钮（发送、登录）是黑色。
- **动效**：位置和大小的变化都是连续的，出现和缩放到位时轻轻回弹一下。具体包括：消息出现、输入栏和通话栏互相替换、角色放大缩小、角色列表和设置面板的进出、换角色时页面色调的渐变、通话时底部的光变亮、按钮按下的回应、登录和选角色页面的依次出现。用户在系统里选了“减少动态效果”时全部关掉。
- **字体**用系统自带的中文字体，不加载网络字体。
- 输入控件字号不小于 16px、可点的东西不小于 44px 的约定没有变，见 `docs/web-mobile.md`。

布局参考了现在主流 AI 对话应用的做法（顶部几个圆形按钮、底部一个浮起的输入栏、通话时输入栏变成声浪），图标、名字和配色是我们自己的。

|---|---|
| `public/roles/<动物>.webp` | 全身像，透明底，720px 高。通话时的角色、登录页、选角色的卡片都用它 |
| `public/roles/<动物>-blink.webp`、`-talk.webp` | 闭眼和张嘴的补丁，和全身像一样大，只有眼睛或嘴那一块不透明 |
| `public/roles/<动物>-face.webp` | 头像，从全身像裁出来的上半身 |
| `app/icon.png`、`app/apple-icon.png` | 浏览器标签和添加到主屏幕的图标 |

动物有三种：`rabbit`、`cat`、`bear`。三个预设角色各对应一种：紫萱是兔子，阿澈是猫，小满是小熊。预设角色总是用为它画的形象，就算这台设备以前给它选过别的动物也一样；从空白开始的角色选了哪种动物就用哪种。没有预设形象、用户也没选过的角色，头像是名字的第一个字，通话时出来的是小熊。

### 图片是怎么做的

都是用 `gpt-image-2.6-flare` 生成的，风格是盲盒手办那种圆润的 3D 卡通形象。

1. 每个角色先用文生图接口出一张正面的全身像，带 `background: "transparent"`，得到的是真正的透明底。
2. 以这张图为参考，用改图接口各出一张“闭眼”和一张“张嘴”，提示词要求其余部分保持不变。
3. 改图出来的图和原图几乎一样，但不是逐像素相同，背景也常常不透明（会画成灰白格子）。所以不直接用它，而是和原图逐像素比较，只取眼睛或嘴那一块真正变了的地方，边缘羽化后存成透明的补丁。这样叠在原图上没有接缝，切换时其余部分完全不动。

第 3 步用的是 `server/main/companion-web/scripts/role-frames.py`，文件开头写了用法。要换一个角色的形象，需要重新走这三步。

关于动图：`gpt-image-2.6-flare` 的文生图接口加 `output_format: "gif"` 可以返回 9 帧的循环动图，但只有文生图接口支持，同样的请求时成时败（10 次成功 4 次），而且它是固定循环、不会跟着声音变，所以没有用它来做角色。

## 验证情况

已经验证的：

- 在本机浏览器里用 375×812 和 1280×800 两种尺寸看过主页面和登录页，浅色和深色都看过。
- 三个角色的全身像、闭眼和张嘴的合成结果都逐张看过。通话时的角色用静音的假麦克风进入通话后在页面上看过。
- 真实发了文字消息：角色先做出“在想”的姿态，然后回复出现。
- 通话栏的样子单独渲染出来看过。
- 桌宠：在手机宽度下拖动过、点开放大过、再缩回去过。
- 桌宠一直在页面上（2026-11-23）：手机宽度下看过它待在开场的话上方、开场的话消失后落到输入栏上方；点开放大、点放大的角色缩回去；1280×800 下放大后站在右侧一栏并且填满那一栏，闭眼补丁和底图对齐。通话时的光圈和字幕只在自动化测试里验证过：内置浏览器不给麦克风，没能在页面上进入通话。
- 角色设置：在页面上打开过一个角色的设置，加了一个性格词并保存，确认它的生效版本从 1 变成了 2、性格已经存下。
- 记忆：在真实对话里说了一句养猫的事，十几秒后角色设置里出现了两条提炼出来的记忆，点“全部忘掉”后清空。
- 自动化测试覆盖了切换和添加角色、开场的话、状态变化、自动朗读的开关、通话时输入栏和通话栏的切换、角色的放大缩小和拖动、关麦克风。

还没有验证的：

- 我这边验证用的浏览器不提供麦克风，所以真实通话里的声浪、角色听的姿态和打断我没有实际看到过；通话本身在普通浏览器里是能拨通的。
- 动效的手感。截图只能看到静止的画面，各处动画的快慢和回弹是否合适需要实际操作来判断。
- 手机真机，原因见 `docs/web-mobile.md`。右滑打开侧栏只有自动化测试，没有在触摸屏上试过；iOS Safari 从屏幕最左边缘右滑是浏览器自己的“返回”，这个手势页面拦不住。
- 新账号第一次选角色、“从空白开始”新建和删除角色的真实流程。测试账号已经有三个角色，到了上限，这几步只有自动化测试。
- 改了性格或提示词之后，角色说话是不是真的变了。只确认了设置已经保存并生效，没有对比过回复。
