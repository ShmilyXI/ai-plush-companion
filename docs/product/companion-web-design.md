# 网页端的产品和界面设计

这份文档记录网页端（`server/main/companion-web`）的设计判断：它是一个什么应用、页面怎么组织、角色怎样出现在页面上、样子怎么定、图片是怎么来的。

**其中的产品判断是草案。** 用户画像、角色形象和文案没有用户数据支持，内测时要看实际使用再调整。

## 它是什么应用

一个陪伴角色的应用，不是聊天工具。打开页面，面对的是角色本人：它在页面中间，会听、会想、会开口说，说过的话同时记成文字。

前期的用户是年轻的成年人。界面的原则：

- **角色是主角，对话记录是配角。** 页面的主体是角色所在的舞台，文字记录放在旁边（手机上收在下面）。
- **开口说是第一位的。** 最大的按钮是麦克风，点一下就进入不用手的持续通话。打字是同样可用的第二种方式。
- **界面本身没有颜色。** 深色的底，颜色只来自角色的光。换一个角色，整个页面的色调跟着变。
- **不复杂。** 一个主页面，没有标签栏、没有需要先配置的东西。连接、会话、模型这些词不出现在界面上。

## 页面

**主页面**由两部分组成。

舞台（手机上占满屏幕，宽屏上在左边）：

- 中间是角色：一个流动的光球，前面坐着它的玩偶。
- 下面是名字、一行状态（在线、在听你说、在想、在说话、通话中、正在重新连接）和字幕。字幕是最近的一句话：用户正在说的，或者角色刚说的。
- 还没和这个角色说过话时，字幕下面有三句可以直接点的开场话。
- 底部是麦克风。点一下开始通话，再点一下结束。通话中直接说话，说完停顿一下就算一句，角色在说的时候可以直接开口打断。
- 左上角是当前角色，点开是角色列表，可以切换和添加。右上角是自动朗读的开关和设置。
- 错误、断线、休息提醒、今天次数用完，以提示条的形式出现在舞台上方。

对话记录（宽屏上固定在右边，手机上点麦克风左边的按钮从底部升起）：

- 通话里语音识别出的话、打字发的话、角色的每句回复，都按顺序记在这里。角色的回复可以点“重听”。
- 底部是打字的输入栏，可以带一张图片。

舞台和对话记录是同一段对话的两种看法，不是两个模式：打字时舞台上的角色照样会想、会开口；通话时对话记录照样在增加。

**其他画面**：登录（三个角色的形象和手机号表单）、选角色（每个角色一张卡片）、设置（当前角色的声音、清空对话记录、协议、退出登录、注销账号）。

## 角色怎样出现在页面上

舞台上的角色由 `components/Presence.tsx` 画出来，有两层。

**光球**是用 WebGL 着色器实时画的。球心是暗的，角色的三种颜色在边缘缓慢流动，外面有一圈光晕。它跟着声音变：

- 用户说话时，跟着麦克风的音量起伏。
- 角色说话时，跟着它自己声音的音量起伏。音量从播放语音的 `AudioContext` 上实时读出来（`lib/playback.ts` 的 `level()`）。
- 角色在想的时候，流动得快一些。
- 连接断开时变暗。

**玩偶**是一张透明底的图，姿态是程序算的：平时轻轻呼吸；听的时候歪一点头；想的时候慢慢左右晃；说的时候跟着声音一颠一颠。

没有玩偶形象的角色（管理台里新加的预设、从管理台进来的角色）只有光球，颜色按名字从几组里固定选一组。

浏览器不支持 WebGL 时，光球退回到样式画的静态版本。用户在系统里选了“减少动态效果”时，只保留很慢的流动，玩偶不动。

### 为什么是光球加玩偶，不是 Live2D 或 3D 角色

三种做法都考虑过：

- **Live2D** 需要专门绑定过骨骼的模型文件，现有的生图工具做不出来，Live2D 的运行库也有单独的授权条件。
- **3D 卡通角色**同样需要建模和绑定好的模型（比如 VRM），以及口型数据。
- **随声音变化的光球**不需要任何素材，现在就能做到流畅。

所以这一版用光球做会动的部分，用生成的玩偶图做角色的形象。`Presence` 只接收三样东西：角色、状态、音量。以后有了 Live2D 或 3D 模型，替换这一个组件就可以，页面其他部分不用改。

## 样子

颜色都定义在 `app/globals.css` 开头的变量里。

- **底色**是接近黑的深色（`#08080c`）。只有深色一种模式，不跟随系统的浅色设置。
- **角色的光**：每个角色三种颜色，写在 `lib/roles.ts`。紫萱是紫和粉，阿澈是蓝和青，小满是黄和橙。光球、页面背后的环境光、头像的底色都用它。
- **控件**是半透明的玻璃质感。最主要的按钮（麦克风、发送、登录）是白色。自己说的话是浅色气泡，角色的话是半透明气泡。
- **字体**：界面用系统自带的黑体；字幕和大标题用系统自带的宋体，没有宋体的设备会退回黑体。不加载网络字体。
- 输入控件字号不小于 16px、可点的东西不小于 44px 的约定没有变，见 `docs/web-mobile.md`。

## 角色形象

三个预设角色是羊毛毡玩偶：紫萱是浅紫色的垂耳兔，阿澈是灰蓝色的猫，小满是蜜黄色的小熊。选玩偶而不是人像，是因为和将来的毛绒硬件是同一个形象，也不会让人往恋爱方向想。

**这也是草案。** 动物、颜色和神态可以整体替换。

| 文件 | 用处 |
|---|---|
| `public/roles/<角色>-body.webp` | 舞台、登录页、选角色卡片上的全身形象，透明底，640px 高 |
| `public/roles/<角色>-face.webp` | 头像，从全身形象裁出来的上半身，256px |
| `app/icon.png`、`app/apple-icon.png` | 浏览器标签和添加到主屏幕的图标 |

角色和图片、颜色的对应关系写在 `lib/roles.ts`，按角色名字匹配。服务端目前不保存这些。

### 图片是怎么生成的

都是用 `gpt-image-2.6-flare` 生成的，通过 mowa-media 的图像接口。

1. 用文字生成紫萱的半身像。
2. 把紫萱的图作为参考，用改图接口生成另外两个角色，这样三个的材质、光线和构图一致。
3. 把每个角色的半身像作为参考，用改图接口加 `background: "transparent"` 生成透明底的全身坐姿。抠出来的边缘是干净的，可以直接放在深色背景上。
4. 裁掉四周空白、缩小、转成 WebP。头像从同一张图裁出来。

**关于动图。** `gpt-image-2.6-flare` 的文生图接口加上 `output_format: "gif"` 可以直接返回 9 帧的循环动图。试过用它做会眨眼的头像，后来没有采用，原因是：

- 只有文生图接口支持，改图接口会拒绝，所以动图不能从已有的角色图改出来，形象对不上。
- 同样的请求时成时败，10 次文生图请求成功了 4 次。
- 每秒只有三四帧，而且它是固定循环，不会跟着声音变。舞台上需要的是实时响应。

## 代码在哪里

| 文件 | 内容 |
|---|---|
| `components/CompanionApp.tsx` | 登录状态、会话、连接、消息这些逻辑，以及主页面的结构 |
| `components/Presence.tsx` | 舞台上的角色：光球和玩偶 |
| `components/RoleFigure.tsx`、`components/Avatar.tsx` | 不会动的角色形象、头像 |
| `components/RoleRail.tsx` | 角色列表 |
| `components/Composer.tsx` | 打字的输入栏 |
| `components/AccountPanel.tsx` | 设置面板 |
| `components/LoginPanel.tsx`、`components/RolePicker.tsx` | 登录、选角色 |
| `lib/roles.ts` | 角色的形象、颜色、短介绍和开场的话 |
| `lib/playback.ts` | 播放角色的语音，并给出当前的音量 |
| `app/globals.css` | 全部样式 |

## 验证情况

已经验证的：

- 在本机浏览器里用 375×812 和 1280×800 两种尺寸看过主页面、对话记录、角色列表、添加角色、登录。
- 真实发了文字消息：舞台上依次出现“在想”和“在说话”，光球随角色的声音起伏，玩偶跟着动，字幕和对话记录同步更新。
- 切换角色后页面色调跟着换，角色先开口。
- 自动化测试覆盖了切换和添加角色、开场的话、状态变化、自动朗读的开关、通话的开始和结束。

还没有验证的：

- **通话没有真的拨通过。** 验证用的浏览器不提供麦克风，所以“光球随用户的声音起伏”和打断没有实际看到过。通话的流程由自动化测试覆盖，其中麦克风和声卡是模拟的。需要在普通浏览器里实际说几句。
- 手机真机，原因见 `docs/web-mobile.md`。光球在低端手机上的流畅程度也没有测过。
- 新账号第一次选角色的真实流程（现有测试账号已经有三个角色）。

## 还没有做的

- 角色的删除和改名、消息的时间、试听声音。
- 浅色模式。
- 角色没有表情，玩偶的神态不会随对话的情绪变化。
- 自己选的声音只在这次打开页面期间有效，刷新后回到角色默认的声音。
- 自动朗读关掉时，服务端仍然会合成语音（这样才能“重听”），这部分成本没有省下来。
