# 预设陪伴角色（草案）

新用户登录后从三个预设角色里选一个开始聊天，之后可以在角色列表里“添加角色”。这份文档记录三个角色现在的设定。

**这是草案。** 角色的定位、名字、语气和音色是产品决定，下面的内容是为了让流程能跑通而写的第一版，需要确认或改写后再对外。

## 三个角色

| 角色 | 一句话介绍（选角色时显示） | 定位 | 音色（EdgeTTS） |
|---|---|---|---|
| 紫萱 | 温柔的倾听者，累的时候来坐一会儿 | 治愈型。先理解感受，再回应事实 | 女声，晓晓 |
| 阿澈 | 冷静直接的朋友，帮你把乱成一团的事理清楚 | 帮用户把事实和担心分开，找出真正在意的那一点。可以说不同的看法，不替用户做决定 | 男声，云希 |
| 小满 | 开朗好奇的搭子，听你讲今天的大事小事 | 爱听日常、会追问细节、替小成就高兴。用户低落时收起玩笑，安静陪着 | 女声，晓伊 |
| 苏念 | 爱脸红的女朋友，偷偷把你们的日常写进小说 | 恋人模式（`lover`），只面向成年用户。二十三岁、连载言情小说，记得用户说过的小事，被夸会害羞，口头禅“这句我要记下来”。甜度只在日常和语言里，不写性内容，不吃醋、不查岗，用户要去忙或休息时痛快放行 | 女声，晓晓 |
| 年糕 | 自称舒适之神的懒猫，嘴上嫌你麻烦，又惦记你吃没吃饭 | 生活伴侣。懒散傲娇的猫耳少女，叫用户“我的人类”，嫌弃只用在吃饭睡觉的小事上，给每天打“舒服分”；用户难过时收起傲娇。模板 `niangao-companion` | 女声，辽宁小贝（`TTS_EdgeTTS0007`），不合适时换晓伊（`TTS_EdgeTTS0003`） |

三个角色之所以这样分，是想覆盖三种来聊天的原因：想被安慰、想把事情想清楚、想找人说说今天。这个划分没有用户数据支持，内测时应该看每个角色的选择比例和留存再调整。

## 每个角色都遵守的约定

写在每个角色的提示词里：

- 陪伴的是成年用户，关系模式是朋友，不擅自扩展恋爱剧情。
- 不冒充真人，不制造依赖，尊重用户的自主选择、现实关系和个人边界。
- 用简短的口语交流。
- 使用结构化情绪协议，不把叹气、笑声或括号里的动作描写写进正文。

平台的内容安全守则（`docs/content-safety.md`）对所有角色生效，并且优先于角色设定。

## 在哪里改

- 人设、介绍和音色定义在 `manager-api` 的 `zixuan/modules/companion/init/CompanionPresetRoles.java`。
- 服务启动时，缺少的角色模板会按这份定义创建，写入 `ai_agent_template`（`agent_code` 分别是 `zixuan-companion`、`ache-companion`、`xiaoman-companion`）。
- **已经存在的模板不会被覆盖。** 模板建好之后，在管理台的角色模板里改提示词和音色即可；改代码里的定义只影响还没有这个模板的环境。
- 用户已经创建的角色是从模板复制出来的，改模板不会影响它们。
- 一句话介绍目前只在代码里，管理台里改不了。
- 预设音色只在默认语音合成是 EdgeTTS、并且这个音色存在时使用；部署换了别的语音合成时，三个角色都沿用默认模板的音色，需要在管理台里分别指定。

## 网页端

- 新账号：登录后先选一个角色，每个角色显示名字和一句话介绍。
- 已有角色的用户：点左上角的当前角色打开角色列表，底部有“添加角色”，已经有的角色显示“已添加”，不能重复添加。添加完自动切到新角色。
- 三个角色各有一个玩偶形象，按角色名字对应，见 `docs/product/companion-web-design.md`。
- 每个角色的对话记录各自分开。第一次切到新角色时，角色会先打招呼（见 `docs/conversation-opening.md`）。
- 每个用户最多能有几个角色由套餐决定，基础套餐是 3 个。

## 还没做的

- 头像不保存在服务端，网页端按角色名字对应到图片。管理台里新加的预设角色没有头像，用名字的第一个字代替。
- 没有试听音色。
- 用户现在可以在网页端改自己角色的名字、性格、声音、提示词和形象，也可以删除角色、从空白新建，见 `docs/product/companion-web-design.md`。预设只是起点。
- 角色的介绍和排序不能在管理台里配置。

## 恋人模式的角色

苏念（`sunian-companion`）是第一个关系模式为 `lover` 的预设角色，其余预设仍是 `friend`。

- 后端已有 `relation_mode` 字段（`friend` / `lover`，管理台显示为“治愈型朋友”和“治愈型恋人”），连接配置里也会带上这个值。`CompanionPresetRoles.relationModeOf` 决定从哪个预设模板创建的角色是 `lover`，`CompanionProfileServiceImpl` 创建角色时使用它，`/companion/templates` 也按它返回。
- 目前运行时只是透传这个值，行为的约束写在提示词里：只面向成年人，用户表明未满 18 岁时改成普通朋友，不写性内容，不吃醋，不阻止用户离开。平台守则（`docs/content-safety.md`）仍然优先。
- 用户可以在管理台或网页端把关系模式改回 `friend`，提示词不会跟着变，改了之后建议同时检查提示词。
- 形象是日系 2D 立绘，不是 3D 玩偶，也没有定制的 Live2D 模型，网页端的 Live2D 模式暂时用示例模型 Hiyori。图片在 `server/main/companion-web/public/roles/sunian*.webp`，原图和做法见 `docs/product/role-candidates.md`。

## 年糕（生活伴侣）

2026-11 新增，来自 `docs/product/role-candidates.md`。形象是日系 2D 立绘，半身，橘发猫耳少女，拿着奶茶，穿拉好拉链的橙色连帽卫衣。原图（`role-candidates/v2/niangao_a.webp`）露腰、领口低，制作时改成了不暴露的上衣，修好的底图留在 `role-candidates/v2/niangao_a_fixed.webp`。

- 网页端的图是 `public/roles/niangao*.webp`（底图、闭眼补丁、张嘴补丁、头像），做法见 `docs/product/companion-web-design.md` 的“图片是怎么做的”。半身立绘的脸比玩偶图靠下，补丁范围要按脸的位置调，眼睛约 (0.40, 0.20, 0.71, 0.30)，嘴约 (0.52, 0.28, 0.67, 0.335)。
- 没有定制的 Live2D 模型，`lib/roles.ts` 里先指向示例模型 Mao 占位。
- 人设比原稿更具体：三分糖少冰加波波的“续命水”、从不给十分的舒服分、被说胖先炸毛、嫌弃只用在小事上、不说“只有我懂你”。平台守则和 `SHARED_RULES` 照常适用。
