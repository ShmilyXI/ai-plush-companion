# 留存与体验数据

内测期间需要回答三个问题：用户会不会回来、回复够不够快、哪里出了问题。本文记录这些数据从哪里来、怎么算。所有数据都不含对话内容。

管理台的“留存与体验”页面展示最近 30 天的结果，对应的接口是 `GET /admin/analytics/overview`，需要超级管理员权限。

## 留存

按注册日期把用户分组，每组看三个数：

- **聊过至少一轮**：注册后有过对话的人数。
- **次日、7 日、30 日留存**：注册后第 1、7、30 天当天有过对话的人数。只算那一天，不是那之前任意一天回来过都算。

第 N 天还没过完时不给数字，页面显示“未到”，避免把“还没到”看成“没回来”。

注册时间取自 `sys_user.create_date`，对话活跃取自 `ai_conversation_usage`。注册时间是一个时刻，按 Asia/Shanghai 折算成日期，不依赖数据库连接的时区设置。

管理员账号不计入。通过 API Key 产生的对话不计入。已注销的账号不再出现在留存里，因为账号已经删除。

## 回复速度

每天的首字耗时取中位数和 90 分位。首字耗时是从 `zixuan-server` 收到用户输入到出现第一段回复文字的时间，语音输入时包含语音识别，不包含语音合成和网络传输。

用户实际听到声音还要再等语音合成，这部分目前没有单独记录。

## 关键行为

网页端在下面这些时刻上报一个事件，只有事件名和少量简单属性：

| 事件 | 含义 |
|---|---|
| `signed_in` | 登录成功 |
| `role_created` | 新账号选好了第一个角色 |
| `mic_started` | 打开了麦克风 |
| `mic_failed` | 麦克风打开失败，属性里带原因，例如没有权限或页面不是 HTTPS |
| `turn_failed` | 一轮对话失败，属性里带错误代码 |
| `reconnect_failed` | 重连多次仍然失败 |
| `quota_reached` | 用完了当天的对话次数 |
| `rest_reminder_shown` | 出现了连续使用的休息提醒 |
| `reply_withdrawn` | 回复被内容安全收回 |
| `reply_replayed` | 点了某条回复的“重听” |
| `history_cleared` | 清空了对话记录 |

事件攒够 20 条或等 2 秒后成批发送，页面关闭时用 `sendBeacon` 发出剩下的。上报失败不重试，也不影响任何功能。

服务端只接受小写字母、数字和下划线组成的事件名。属性最多 8 个，值只能是数字、布尔或不超过 80 个字符的文字，嵌套结构直接丢弃，所以属性里放不下一段对话。一次请求最多记 20 条。

事件保存在 `ai_client_event` 表里。账号注销时这个账号的事件一并删除。

只有手机号登录的用户会上报事件。从管理台进入的会话不上报。

## 尚未处理

- 没有登录前的数据：有多少人打开了页面、有多少人请求了验证码但没有登录。
- 没有按角色、按输入方式拆分的留存。
- 没有语音合成耗时和端到端的“听到声音”耗时。
- 数据量大了以后，留存和分位数应该改成定时汇总，而不是每次打开页面现算。
