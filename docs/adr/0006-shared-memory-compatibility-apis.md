# ADR 0006 硬件与 App 的共享记忆兼容接口

## 状态

已接受

## 背景

现有硬件运行时和管理接口按设备身份访问陪伴记忆。消费者 App 需要按用户和陪伴角色查看、编辑和清理记忆。若直接把硬件接口改成角色参数，会破坏设备链路；若维护两份互不相通的记忆，又会让设备和 App 的互动无法互相学习。

## 决策

保留硬件侧按设备身份的记忆接口，并新增消费者 App 按用户和角色的记忆接口。两套接口都映射到同一份逻辑记忆。设备身份只用于解析当前设备绑定的用户和角色，不作为记忆的业务归属；App 直接使用用户和角色归属。

硬件和 App 的运行时读取与自动写入必须经过统一的记忆策略，包括角色级记忆开关和权限校验。开关关闭时，AI 不召回也不自动新增；用户管理接口仍允许查看、编辑、删除和清空已有记忆。旧的设备迁移接口继续保留，用于历史数据迁移或兼容处理，不作为消费者 App 的主流程。

同一角色绑定多个设备时，设备和 App 共享该角色记忆。App 的修改在设备下一次请求时可见；设备切换角色后，下一轮只读取新角色记忆，旧角色记忆保留。

## 取舍

兼容接口可以保护已有硬件协议，同时满足跨设备、跨入口共享记忆。代价是服务端需要维护设备到角色的解析和一致性处理，不能用简单的双写副本代替逻辑归属。
