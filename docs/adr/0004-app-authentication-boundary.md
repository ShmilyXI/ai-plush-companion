# ADR 0004 消费者 App 独立认证边界

## 状态

已接受

## 背景

现有后台登录流程使用密码和兼容旧客户端的图形验证码协议，短信验证码主要服务于手机注册和找回密码。消费者 App 需要支持手机号或邮箱的密码登录、验证码登录、验证码注册和验证码找回密码，且首期不要求图形验证码。

## 决策

为消费者 App 提供独立的认证 API 和验证码生命周期。用户可以用手机号或邮箱加密码登录，也可以用手机号或邮箱加一次性验证码登录。注册必须验证手机号或邮箱验证码并设置密码；找回密码必须验证同一联系方式的验证码后才能设置新密码。App 不直接复用后台登录请求体，也不要求图形验证码。

App 认证成功后仍进入统一用户体系，设备、角色、对话和记忆继续按同一用户身份授权。验证码发送、校验、失效、频率限制和联系方式归属校验由服务端负责。

一个账号可以同时绑定手机号和邮箱，注册时先验证其中一个，另一个可在账号设置中后续绑定。手机号和邮箱都全局唯一，用任一已绑定联系方式登录都解析到同一用户，不创建重复账号。

## 取舍

独立边界可以让 App 认证体验不受后台旧协议牵制，也能安全加入邮箱验证码。代价是服务端需要新增邮箱发送通道、验证码风控和与既有用户表的兼容映射。
