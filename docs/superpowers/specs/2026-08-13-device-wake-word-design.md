# 按设备动态唤醒词设计

## 目标

让每台设备可以在后台配置自己的中文唤醒词。后台自动生成对应的 `assets.bin`，自动上传并下发，设备自动下载、校验、重启和切换。更新失败时继续使用旧唤醒词，不影响设备原有语音唤醒能力。

## 首期边界

首期使用现有 `assets.bin` 资源分区和 `self.assets.set_download_url` 下发链路，不新增独立模型下载协议。

唤醒词按设备保存，不跟随智能体或用户全局配置。首期接受二到八个中文汉字，输入值需要做 Unicode 长度校验和首尾空白清理。英文、中英混合、多个唤醒词同时识别和在线训练不在首期范围内。

后台的 `wakeup_words` 继续作为服务端 ASR 后的唤醒词判断列表，但设备当前生效词必须由设备版本状态同步后加入列表。它不能替代设备端模型。

## 现有能力

设备端已经支持资源分区、`assets.Download`、启动时 `CheckAssetsVersion` 和 `self.assets.set_download_url`。自定义唤醒词资源通过 `index.json` 的 `multinet_model` 配置加载，固件中的 `CustomWakeWord` 会读取 commands、threshold、duration 和模型资源。

后台已经有资源生成器、`uploadAssetsBin` 接口和设备侧 MCP 工具调用能力。现有生成器的浏览器逻辑需要抽出为可复用的服务能力，不能依赖管理员浏览器的本地存储和手工点击。

## 总体架构

后台增加设备唤醒词配置和更新任务。设备保存期望唤醒词、任务状态、候选资源版本、当前生效版本、资源地址、文件哈希和错误信息。

用户提交新唤醒词后，后台创建一个不可重复的更新任务。任务生成资源包，校验资源包，上传资源，等待设备在线，然后调用设备的 `self.assets.set_download_url`，再调用 `self.reboot`。设备启动后通过设备配置上报实际加载的资源版本。后台收到匹配版本后才将任务标记为已生效，并同步服务端 `wakeup_words`。

设备必须保留旧资源直到新资源完成下载、校验和模型加载。新资源失败时恢复旧资源并上报失败原因。后台不会因为设备离线或更新失败删除旧配置。

## 后台数据模型

新增 `device_wake_word` 表，每台设备一行，核心字段如下。

| 字段 | 说明 |
| --- | --- |
| `device_id` | 设备 ID，唯一外键 |
| `desired_word` | 后台期望唤醒词 |
| `desired_version` | 期望资源版本，单调递增 |
| `active_word` | 设备确认生效的唤醒词 |
| `active_version` | 设备确认生效的资源版本 |
| `candidate_url` | 候选 `assets.bin` 下载地址 |
| `candidate_sha256` | 候选文件哈希 |
| `status` | 当前更新状态 |
| `last_error_code` | 最后一次失败码 |
| `last_error_message` | 最后一次失败说明 |
| `created_at`、`updated_at` | 审计时间 |

状态只允许 `IDLE`、`GENERATING`、`WAITING_DEVICE`、`DOWNLOADING`、`WAITING_REBOOT`、`ACTIVE`、`FAILED`。新的配置提交会递增 `desired_version`，并使旧任务失效。任务执行器必须用版本条件更新，防止旧任务覆盖新配置。

## 后台接口

新增设备唤醒词接口，路径建议为 `/admin/device/{deviceId}/wake-word`。

`GET` 返回设备当前状态、期望词、生效词、期望版本、生效版本、任务状态、失败信息和更新时间。

`PUT` 接收 `{ "word": "小布小布" }`。服务端清理首尾空白、校验二到八个中文汉字、拒绝控制字符和空值。相同唤醒词不创建新任务，直接返回当前状态。

`POST /retry` 仅允许重试失败任务，不改变期望词和版本。

设备状态上报扩展现有配置或设备心跳数据，增加 `wake_word_version`、`wake_word_status`、`wake_word_error`。优先复用现有设备配置上报入口，避免新增长连接协议类型。

## 资源生成和上传

生成器服务复用 `server/main/manager-web/public/generator/static/multinet_model` 中的模型资源和现有 `assets.bin` 格式。服务端生成内容至少包括模型文件、`index.json` 和资源版本元数据。`index.json` 中的 command text 使用后台唤醒词，command 使用对应中文拼音，action 固定为 `wake`。

生成器必须在服务端验证目标芯片和模型版本，生成完成后计算 SHA-256。上传接口返回带版本和哈希的下载地址，资源文件按不可变版本命名，禁止覆盖已发布资源。

生成服务失败、资源过大、模型不存在或哈希计算失败时，任务进入 `FAILED`，不触碰设备当前生效资源。

## 设备端流程

固件启动时读取当前资源版本和旧资源备份。后台下发地址时，设备把地址写入候选更新设置，不立即删除当前资源。

设备下载完成后校验 HTTP 完整性、文件大小、SHA-256、芯片型号和 `index.json` 结构。校验通过后以候选资源初始化 `CustomWakeWord`，确认模型和 command 可加载，再原子切换当前资源指针并重启。

重启后设备上报实际生效版本和唤醒词。若候选资源加载失败，设备恢复旧资源指针、删除不完整候选资源并上报错误。没有旧资源时才回退到固件内置默认资源。

设备在更新期间保持按键唤醒可用。下载或切换过程中的语音唤醒可以短暂暂停，但失败后必须恢复旧模型并重新启动检测。

## 服务端同步规则

服务端只把 `active_word` 加入运行时 `wakeup_words`。`desired_word` 在设备确认生效前不参与服务端唤醒词判断，避免后台已经改名但设备仍只能识别旧词时产生误判。

设备确认新版本后，后台更新设备级唤醒词缓存并刷新配置缓存。旧的设备唤醒词从设备级列表移除；保留系统默认词是否继续识别由平台全局开关决定。

## 页面

在设备管理的设备操作中增加唤醒词设置区域，显示当前生效词和更新状态。输入框只展示首期支持范围，提交后立即显示生成中、等待设备、等待重启等状态。失败状态显示最后错误和重试按钮。设备离线时允许保存，状态显示等待设备上线。

页面不再要求管理员打开生成器、下载文件或手工调用 MCP 工具。现有主题生成器继续保留，作为高级资源编辑入口，不与自动唤醒词更新流程混用。

## 安全和并发

设备更新地址使用带权限校验的短期或不可猜测 URL。资源下载接口只允许访问已发布的 `assets.bin` 文件，不接受任意本地路径。

同一设备同一时刻只允许一个活动任务。新词提交通过数据库唯一键和版本条件取消旧任务。设备上报必须校验设备身份，不能仅凭资源版本更新任意设备状态。

## 测试策略

后台测试覆盖唤醒词校验、相同词幂等、版本递增、旧任务失效、设备离线等待、生成失败、上传失败、重试和设备确认后的服务端词表同步。

资源生成测试覆盖中文词到拼音 command 的转换、`index.json` 结构、SHA-256、芯片模型匹配和不可变文件名。

固件测试覆盖候选资源下载校验、模型加载失败回滚、重启后版本上报、旧模型保持可用和无旧资源时回退内置模型。至少增加一个离线解析 `index.json` 的单元测试和一个更新状态机测试。

端到端验证使用一台支持 assets 分区的 2.0 以上设备，依次验证在线更新、离线后上线更新、下载中断、错误资源、重启确认和旧词不可用、新词可用。

## 分阶段交付

第一阶段完成数据库、后台接口、状态机和页面，只支持生成任务模拟结果，验证设备级数据和状态展示。

第二阶段完成服务端资源生成、上传和不可变资源下载地址，加入生成器和资源包测试。

第三阶段完成固件候选资源、校验、回滚和版本上报，先用固定测试下载地址验证。

第四阶段接通后台任务执行器、设备在线检测、MCP 下发和自动重启，完成端到端更新。

第五阶段补齐失败重试、日志审计、监控指标、文档和灰度发布开关，默认只对支持 assets 分区的设备开放。

## 明确不做

首期不修改 WakeNet 固定模型，不做任意语言在线训练，不做多个唤醒词同时启用，不把设备端唤醒词降级为云端 ASR 轮询，也不删除现有手工 assets 生成器。
