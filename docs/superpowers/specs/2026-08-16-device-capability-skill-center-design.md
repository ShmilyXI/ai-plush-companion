# 设备能力与 Skill 中心设计

## 目标

项目新增统一能力中心，让天气、新闻、搜索等对话能力以 Skill 形式在后台管理。管理员可以自由创建 Skill，但 Skill 只能组合已注册的 Plugin、MCP 和设备工具，不能上传或执行任意代码。Skill 跟随设备生效，同一个全局 Skill 模板可以绑定多台设备，每台设备可以独立启停并覆盖允许修改的参数。

现有音量和亮度后台控制保持原有使用方式。人工控制和 AI 对话最终调用同一个设备 MCP 工具，避免维护两套设备操作协议。

## 范围

本设计覆盖统一能力目录、Skill 模板、混合触发规则、工具引用、设备绑定、设备参数覆盖、版本发布、运行时配置下发、缓存失效、执行记录、管理后台页面，以及天气、新闻、搜索三个现有插件向 Skill 的迁移。

Plugin 的可执行代码继续由 `xiaozhi-server` 部署。服务端 MCP 连接从本地 JSON 迁入后台管理。设备 MCP 工具继续由固件动态上报。后台不提供 Python、JavaScript、Shell 或其他任意代码执行入口。

## 核心概念

能力目录是统一管理入口。目录中的对象分为 Skill、Plugin、MCP 服务和设备工具。它们共享名称、说明、状态、版本、创建者和审计信息，但保留不同的执行模型。

Skill 是配置和编排层。它描述用户何时需要某项能力、模型应该怎样理解请求、允许调用哪些工具、使用哪些默认参数、执行成功后怎样组织回复。Skill 本身不执行网络请求或设备操作。

Plugin 是本地执行器。它通过稳定的执行器标识引用 `xiaozhi-server` 中已经部署的 Python 函数。后台可以管理参数 Schema、密钥字段、启停状态和展示信息，不能修改运行代码。

MCP 服务是外部工具提供者。后台管理连接方式、地址、启动参数、请求头、密钥引用和工具白名单。运行时连接成功后获取真实工具列表，并将工具与后台登记信息进行校验。

设备工具是设备固件通过 MCP 上报的真实硬件能力。后台保存最近一次能力快照和 Schema，只允许绑定设备实际上报过的工具。设备离线或固件不支持时，能力保持可见但不可执行，并显示原因。

## 系统边界

`manager-api` 是控制面，负责能力目录、Skill 编辑、版本发布、设备绑定、设备覆盖参数、密钥、权限、审计和有效配置计算。

`companion-console` 是统一管理界面，提供能力中心、Skill 编辑器、Plugin 管理、MCP 管理和单设备能力配置。旧 `manager-web` 的插件配置在迁移期继续可用，最终由新控制台替代。

`xiaozhi-server` 是执行面。它按设备读取已发布的有效配置，完成 Skill 路由、提示词注入、工具选择和执行。它不拥有配置真相，不接受会绕过后台版本和权限的本地配置覆盖。

固件继续暴露设备 MCP 工具。音量、亮度、相机、资源下载和重启等能力仍由固件决定。后台只能授权和调用，不能让不支持该工具的设备获得虚假的硬件能力。

## 数据模型

`ai_capability` 保存能力的公共元数据。核心字段包含能力编号、能力类型、名称、说明、状态、当前草稿版本、已发布版本、创建者、更新时间和逻辑删除标记。能力类型限定为 `SKILL`、`PLUGIN`、`MCP_SERVER` 和 `DEVICE_TOOL`。

`ai_capability_version` 保存不可变版本内容。每次发布生成新版本，内容使用 JSON 保存，并记录内容摘要、发布者和发布时间。草稿内容可以修改，已发布版本不能原地覆盖。

`ai_skill_definition` 保存 Skill 草稿配置，包含执行提示词、触发模式、规则组合方式、语义判断阈值、回复策略、超时和失败提示。触发模式固定为混合模式，规则命中优先，语义判断作为补充。

`ai_skill_trigger` 保存 Skill 的触发规则。规则支持关键词、正则表达式和正反例句。关键词和正则用于确定性匹配，例句用于语义匹配。规则保存优先级、是否区分大小写和启用状态。

`ai_skill_tool_mapping` 保存 Skill 可以使用的工具。映射引用 Plugin 工具、MCP 工具或设备工具，并保存别名、用途说明、默认参数、是否必需和排序。运行时只能向模型暴露当前 Skill 映射中的工具。

`ai_device_skill_mapping` 保存设备与 Skill 的绑定。映射包含设备编号、Skill 编号、固定版本或跟随最新发布版本、启用状态、设备覆盖参数、触发优先级和配置版本。Skill 跟随设备，不跟随角色迁移。

`ai_plugin_definition` 保存 Plugin 的执行器标识、输入 Schema、配置 Schema 和密钥字段说明。执行器标识必须与 `xiaozhi-server` 中已注册的函数名称一致。

`ai_mcp_server` 保存 MCP 连接配置，支持 stdio、SSE 和 Streamable HTTP。敏感字段不进入普通配置 JSON，而是引用后台密钥记录。MCP 服务与设备的授权通过独立映射保存，不默认对所有设备开放。

`ai_mcp_tool_snapshot` 保存 MCP 服务最近成功获取的工具列表、Schema、同步时间和状态。工具白名单引用快照中的稳定工具名。服务端实际返回的工具发生变化时，后台标记差异并等待管理员确认，不自动扩大权限。

`ai_device_tool_snapshot` 保存设备最近上报的工具和 Schema。工具记录与设备型号、固件版本和最近上报时间关联，用于配置校验和后台展示。

## 配置继承

有效配置按照设备覆盖值、Skill 已发布版本默认值、工具默认值的顺序合并。设备只能覆盖 Skill 明确声明为可覆盖的字段。密钥字段只能选择已有密钥引用，不能把明文写入设备覆盖 JSON。

设备绑定可以选择跟随最新发布版本，也可以固定版本。跟随最新版本的设备在新版本发布后自动获得新的配置版本。固定版本设备保持不变，直到管理员手动切换。

角色切换不会改变设备能力绑定。多个角色在同一设备上使用相同的 Skill 集合。Skill 执行时仍然使用当前角色的系统提示词和表达风格，但不能改变 Skill 的工具授权。

## Skill 触发与执行

每轮用户输入先进入 Skill 路由器。路由器从当前设备的有效 Skill 集合中进行确定性匹配。关键词和正则命中后，根据规则优先级、匹配长度和设备绑定优先级选择候选 Skill。唯一高置信候选可以直接选中。

没有规则命中、多个候选冲突或规则要求语义确认时，路由器进行语义判断。第一版复用当前设备选择的主 LLM，发起一次非流式、小输出上限的结构化分类请求。语义阶段只接收 Skill 编号、名称、用途说明和正反例句，不接收完整工具 Schema，也不接收密钥或连接配置。模型只能返回候选 Skill 编号和置信结果。结果低于阈值、格式错误或请求超时时不选择 Skill，继续普通对话。

Skill 选中后，运行时加载该 Skill 的执行提示词、允许工具和设备覆盖参数。主模型只看到该 Skill 允许的工具。模型完成 Function Calling 后，现有 `ToolManager` 根据工具类型调用 Plugin、服务端 MCP、设备 MCP 或 MCP Endpoint 执行器。

执行结果继续进入现有对话流程。Skill 的回复策略可以要求模型基于结果生成自然语言，也可以让确定性的设备操作返回固定成功文案。失败时使用 Skill 配置的失败提示，不允许把失败包装成成功。

当前 `connection.py` 中写死的工具关键词路由由 Skill 路由器替代。过渡期间保留兼容开关，但天气、新闻、搜索迁移完成后不再依赖代码内关键词表。

## 运行时配置

`manager-api` 提供按设备获取有效能力包的内部接口。能力包包含设备配置版本、已启用 Skill 的已发布内容、允许工具引用、设备覆盖参数和必要的非敏感执行配置。执行器需要的密钥通过独立的服务端内部接口读取，只进入 `xiaozhi-server` 进程内存，不进入前端响应、设备消息、普通配置缓存或日志。

`xiaozhi-server` 按设备缓存有效能力包。缓存键包含设备编号和配置版本。后台发布 Skill、修改设备绑定或更新 MCP 授权时增加配置版本，并通过现有配置刷新机制或轻量通知使缓存失效。正在执行的对话继续使用本轮开始时的配置快照，下一轮使用新版本。

运行时读取后台失败时可以使用最后一次成功缓存，最长五分钟。后台主动停用或撤销绑定时发送配置失效通知，并立即清除对应设备缓存。缓存不存在或超过五分钟时，仅保留普通对话和设备必要系统工具，不加载无法确认权限的 Skill。

## Plugin 管理

现有 `ai_model_provider` 中 `model_type = Plugin` 的数据迁移到统一能力目录。迁移完成后 `ai_capability` 和 `ai_plugin_definition` 是唯一配置真相。兼容期只允许旧接口读取统一目录的投影，不再允许旧表独立写入，避免同一个 Plugin 同时存在两套目录真相。

Plugin 创建时只能选择服务端已经登记的执行器标识。`xiaozhi-server` 暴露内部执行器清单接口，后台定期同步名称和 Schema。后台存在但服务端未部署的 Plugin 标记为不可用，不能绑定到新 Skill。

天气、新闻和搜索现有参数迁入 Plugin 配置。现有每个智能体的插件映射迁移到该智能体当前关联的每一台设备，生成设备 Skill 绑定和设备覆盖参数。没有关联设备的旧映射保留在迁移记录中，等待设备关联后补迁，不静默丢弃。迁移完成后新设备不会继承角色或智能体的旧插件映射，能力只能通过设备绑定获得。

## MCP 管理

现有 `data/.mcp_server_settings.json` 的连接定义迁入 `ai_mcp_server`。迁移工具读取 command、args、env、url、transport 和 headers，把敏感值写入密钥存储，普通配置只保存引用。

后台提供连接测试和工具同步。连接测试不授予工具权限。同步成功后管理员选择允许使用的工具，再把这些工具加入 Skill。stdio MCP 只允许管理员配置预先批准的命令模板，不能在后台自由输入任意系统命令。

现有 `server.mcp_endpoint` 继续承担把智能体工具暴露给外部 MCP 客户端的职责，不与外部 MCP 服务连接配置混用。后台页面会明确区分外部 MCP 服务和智能体 MCP 接入点。

## 设备工具和人工控制

设备详情页现有音量和亮度控制继续调用 `CompanionDeviceServiceImpl.command`。能力中心不替换这条人工操作链，只把同名设备工具登记到能力快照，并允许 Skill 引用。

AI 调用音量和亮度时同样使用 `self.audio_speaker.set_volume` 和 `self.screen.set_brightness`。权限校验、在线状态、参数 Schema 和调用结果验证复用现有设备工具服务。设备未上报亮度工具时，相关 Skill 在该设备上显示不可用。

## 管理界面

能力中心首页按类型查询 Skill、Plugin、MCP 服务和设备工具，展示草稿、已发布、不可用和停用状态。设备工具只读展示，其他能力根据权限创建和编辑。

Skill 编辑器包含基础信息、执行提示词、混合触发、工具选择、默认参数、可覆盖字段、回复策略和调试区域。调试区域允许输入一句用户话术，展示规则命中、语义候选、最终 Skill、可用工具和模拟参数，不执行真实设备操作，除非管理员明确进入真实调用模式。

设备详情增加能力配置页，展示已绑定 Skill、版本策略、启停状态、覆盖参数和不可用原因。音量与亮度人工控制仍保留在设备控制卡片中。

MCP 页面提供连接配置、连接测试、工具同步、工具白名单和引用该 MCP 的 Skill。密钥字段只显示是否已配置，不回显明文。

## 权限与审计

只有平台管理员可以创建 Plugin 定义、MCP 服务和全局 Skill。普通设备所有者只能给自己的设备绑定平台允许的 Skill，并修改被声明为可覆盖的参数。若当前产品只开放管理员后台，接口仍保留这层权限边界。

Skill 发布、设备绑定、参数覆盖、MCP 连接修改、工具白名单变化和真实调试调用都写入审计日志。日志保存能力编号、设备编号、版本、操作人、结果和错误类型，不记录密钥、完整系统提示词或模型内部推理。

## 错误处理

Skill 引用不存在或停用工具时不能发布。已发布 Skill 的工具后来不可用时，Skill 保持可见并进入降级状态，后台显示具体原因。

MCP 连接失败、设备离线、工具超时和参数校验失败使用统一错误类型。运行时最多进行执行器自身允许的有限重试。具有副作用的设备工具默认不自动重试，避免重复执行。

语义路由无法确定 Skill 时返回普通对话，不把低置信结果当作工具请求。多个高优先级规则冲突时记录冲突事件，并进入语义确认，不能按数据库返回顺序随机选择。

## 迁移和兼容

天气、新闻和搜索首先登记为 Plugin 能力，再创建官方 Skill 模板引用对应 Plugin。旧插件选择按设备归属迁移为设备 Skill 绑定。迁移期间运行时同时支持旧插件映射和新能力包，但同一工具只保留一份描述，避免重复暴露给模型。

新能力包稳定后，停止从 `Intent.functions` 和旧插件映射计算工具列表。旧 `manager-web` 插件页面改为只读提示并引导到 `companion-console`，最后再删除旧写入口。

服务端 MCP 采用相同方式渐进迁移。本地 JSON 存在时只作为一次性导入源。后台 MCP 配置启用后，运行时不再同时读取本地文件，避免配置冲突。

## 测试与验证

Java 测试覆盖能力 CRUD、发布不可变性、设备归属、版本跟随、固定版本、覆盖字段限制、密钥隔离、有效配置计算和迁移。权限测试必须证明普通用户不能修改不属于自己的设备，也不能创建可执行器或 MCP 连接。

Python 测试覆盖规则路由、语义回退、冲突处理、低置信普通对话、Skill 工具隔离、配置缓存失效、后台暂时不可用、Plugin 执行、MCP 执行和设备工具执行。测试需要证明未绑定 Skill 的工具不会进入模型工具列表。

前端测试覆盖 Skill 编辑、触发规则校验、工具选择、设备绑定、参数覆盖、版本切换、不可用原因、MCP 密钥不回显和错误状态。

端到端验证使用两台设备绑定不同的天气 Skill 参数，确认相同话术得到各自配置。还要验证新闻和搜索不再依赖硬编码关键词，角色切换不改变设备 Skill，设备移除 Skill 后下一轮对话立即失去该能力，设备离线时后台人工控制和 AI 调用都返回真实失败。

## 完成标准

管理员可以在 `companion-console` 自由创建只组合现有工具的 Skill，配置混合触发和提示词，发布版本，并绑定到指定设备。天气、新闻和搜索通过官方 Skill 使用，且每台设备可以独立启停和覆盖参数。

后台可以管理 Plugin 元数据和外部 MCP 服务，运行时从后台获得有效配置，不再依赖天气新闻搜索的静态 YAML 选择，也不再依赖服务端 MCP 本地 JSON。设备工具仍由固件动态上报，音量和亮度的人工控制保持可用，AI 调用复用同一工具链。

测试和端到端证据必须证明设备隔离、权限隔离、工具隔离、版本生效、配置刷新、错误反馈和现有设备控制没有回归。
