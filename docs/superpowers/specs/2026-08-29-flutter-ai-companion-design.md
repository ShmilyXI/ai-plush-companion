# Flutter AI 陪伴 App 设计

## 目标

新增一个面向普通用户的 Flutter Android/iOS App。它与现有 `manager-mobile` 管理端并存，直接对接 `manager-api` 和公共对话运行时，提供完整的首期用户闭环：账号认证、角色管理、文字聊天、单轮语音、全屏实时语音通话、会话历史、记忆管理、设备配网与绑定，以及基础设备控制。

首期使用中文界面，代码保留国际化结构。订阅套餐介绍、购买、权益运营和高级设备运维不进入首期。

## 现有事实

仓库目前没有 Flutter 工程。`server/main/manager-mobile` 是 UniApp 管理端，不能改造成消费者 App。`server/main/companion-web` 已验证公共 WebSocket 的文字、按次音频和持续 PCM 音频流程，可作为 Flutter 协议适配的行为参考。

公共会话接口已经提供 `POST /api/v1/conversations`、角色/模型/音色/设备资源查询和按会话历史查询。Python WebSocket 支持 `web.session.start`、16 kHz 单声道 PCM 二进制帧、`input.audio.commit`、`stream.stop`、取消、流式文字、TTS 音频和心跳。当前会话 runtime token 约 15 分钟，历史索引只在 Redis 临时保存，不能支持长期会话侧栏。

陪伴设备接口已经提供设备列表、六位激活码绑定、改名、角色切换、音量、亮度和解绑。固件配网网页固定在 `http://192.168.4.1`，`POST /submit` 成功后跳转 `/done.html`，完成页请求 `/exit`。App 可以复用该网页，不需要接入 MQTT。

当前角色接口支持从模板创建、读取、更新和删除，普通更新只保存草稿并创建快照；App 需要一个保存、发布、激活的一体化服务端动作。当前硬件记忆按设备命名空间，公共会话记忆按会话命名空间，均与用户确认的用户加角色逻辑归属不一致。

## 领域规则

用户账号可以同时绑定一个手机号和一个邮箱，联系方式全局唯一。密码始终存在。登录支持手机号或邮箱加密码，也支持手机号或邮箱加一次性验证码。注册和找回密码都必须验证对应联系方式的验证码；首期不使用图形验证码。App 使用独立认证 API，但认证成功后进入统一用户授权体系。

后台预设角色只用于创建用户副本。用户可以编辑副本的名称、形象、关系、性格、系统提示词、模型、音色和能力开关，修改不会改变预设。编辑采用显式保存，App 的一个保存动作由服务端原子完成保存、发布和激活。当前会话继续使用创建时的角色版本，新 App 会话和设备下一轮使用新版本。绑定设备的角色不能直接删除；删除后角色从可选列表隐藏，历史对话和记忆保留。

一个设备有一个当前陪伴角色。设备切换角色后，正在进行的轮次继续使用旧角色，下一轮使用新角色。App 切换角色立即新建会话。

文字聊天、单轮语音输入和实时语音通话属于同一个用户与角色对话。聊天页左侧抽屉管理会话，右侧抽屉管理角色。设备产生的语音对话也进入同一历史索引，App 可以在设备会话结束后查看转写并继续，但不接管设备正在进行的实时连接。

记忆按用户加角色共享。硬件和 App 保留两套访问接口，硬件接口继续按设备身份接入，App 接口按用户和角色接入，两者映射到同一份逻辑记忆。同一角色绑定多个设备时共享记忆，切换角色后下一轮只读取新角色记忆。角色记忆开关是长期设置，角色页和聊天页都能修改；关闭后不读取、不新增，已有内容保留。记忆首期只支持查看、编辑单条、删除单条和清空全部，不支持手动新增。删除会话不删除记忆。

自动播放是 App 全局音频偏好，不属于角色配置。每条 AI 回复保留手动播放入口，同一时间只播放一条，播放新回复会停止上一条。回复音频和实时通话支持后台与锁屏；通知提供暂停、继续、返回和停止/结束控制。用户原始录音和整段通话录音不长期保存，只保留文字转写；回复音频按需生成并临时缓存。

## 客户端架构

Flutter 工程位于仓库根目录 `app/`，只构建 Android 和 iOS。推荐使用 Riverpod 管理状态，go_router 管理认证分支和主导航，Dio 封装 REST，独立 WebSocket 适配层处理 runtime 会话，`record` 提供跨平台录音流，`just_audio` 负责音频解码播放，`audio_service` 负责后台播放、锁屏控制和系统通知，`webview_flutter` 承载设备配网页面。依赖版本在建工程时锁定当前稳定主版本，并由锁文件固定。

客户端分为三层。页面层只负责布局、输入和路由；业务状态层维护认证、角色、设备、会话、记忆和音频状态机；基础设施层负责 HTTP、WebSocket、系统音频、权限、通知、WebView 和安全存储。访问 token 和 refresh token 只写入 Keychain/Keystore，runtime token 只存在当前会话对象中，不进入持久日志。

App 直接调用 `manager-api` 的 HTTPS REST 接口。创建或续接对话后，服务端返回短期 runtime token 和 Python WebSocket 地址，App 直接建立 WebSocket，不经过 BFF，也不把 App 伪装成硬件。设备配网是唯一的本地 HTTP 链路。

## 页面与状态

认证分支包含启动恢复、密码登录、验证码登录、注册、找回密码和联系方式绑定。首次登录且没有角色时，先选择预设或自定义角色，设备绑定可以跳过；已有用户恢复最近会话，没有历史时创建新会话。

主导航包含聊天、设备、角色和我的，聊天是默认首页。聊天页顶部左侧按钮打开会话侧栏，列出 App 和设备来源的会话并支持新建、继续、重命名和删除；顶部右侧角色按钮打开卡片侧栏，卡片显示形象、名称和简介，当前角色有选中态，并提供长期记忆开关。切换角色前检查当前会话是否有未发送内容，确认后新建会话。

聊天输入支持文字和单轮语音。录音按钮按住开始，松开提交，上滑后松手取消；录音中显示计时和振幅。文字和语音都通过同一会话 WebSocket 发送，回复文字增量实时显示，TTS 音频进入统一播放队列。网络失败保留草稿，不自动重复提交。

聊天页电话按钮进入全屏通话页。通话进入后默认开启麦克风和免提，客户端持续发送 16 kHz 单声道 PCM，并用本地 VAD 识别说话和停顿；停顿后发送 `input.audio.commit`。AI 播放期间继续监听，检测到用户说话立即发送取消并清空播放队列。静音只关闭上传，挂断才结束会话；通话可切到其他 App 或锁屏后继续，结束后回到原聊天并刷新转写。

设备页只包含在线状态、改名、当前角色、音量、亮度、重新配网和解绑。配网向导先引导手机连接设备热点，再在 WebView 打开现有页面；导航到 `/done.html` 后关闭 WebView，等待设备重新上线，最后输入六位激活码并选择角色。系统不允许自动切换 Wi-Fi 时，向导打开系统 Wi-Fi 设置并在 App 回前台后恢复步骤。

角色页包含角色卡片列表、新建入口和编辑页。新建可选择后台预设或自定义起点。编辑页分为身份、模型与音色、性格与提示词、能力、记忆和绑定设备区域；能力只显示服务端授权目录的开关，不显示 URL、密钥、脚本或自定义 MCP。保存失败不更新本地已生效版本，离开页面时有未保存保护。

记忆页按角色展示自动产生的记忆，支持单条编辑、单条删除和全部清空。我的页面展示账号、手机号/邮箱绑定、修改密码、退出登录和自动播放偏好；首期不放套餐购买入口。

## 服务端契约

### App 认证

本设计固定使用 `/app/auth` 前缀。发送验证码请求包含联系方式、渠道和用途（登录、注册、找回、绑定），返回一次性 challenge 标识、过期时间和重试时间。验证码只保存哈希并限制尝试次数、发送间隔和每日额度。

密码登录和验证码登录分别返回短期 access token 与可撤销 refresh token。注册请求必须同时携带已验证 challenge 和新密码；找回密码请求必须携带已验证 challenge 后设置新密码。手机号和邮箱统一映射到同一用户表或联系方式表，写入唯一约束。现有后台登录接口保持兼容，不让 Flutter 复用旧图形验证码请求体。

### 角色与能力

保留现有 `/companion/profiles` 的管理权限边界，新增消费者语义的模板目录、能力目录和原子保存接口。原子保存接口负责校验用户归属、模型和音色匹配、能力仍处于已发布授权状态，然后在一个事务边界内更新草稿、创建版本、发布并激活。响应返回新的 active version 和完整公开配置，不返回 provider 凭据。

角色详情增加 `memoryEnabled` 和公开的能力开关状态。角色删除改为软删除或隐藏状态，仍绑定设备时拒绝操作；历史查询可以解析已隐藏角色的名称快照。

### 设备

继续使用 `/companion/devices` 的列表、详情、绑定、改名、角色切换、音量、亮度和解绑路由。绑定请求仍使用六位激活码和可选 `profileId`。App 不调用旧的 `/device/*` 设备伪装路由，也不接 MQTT。

### 持久会话

历史回复重新播放使用 `POST /api/v1/conversations/{conversationId}/turns/{turnId}/audio`，只返回短期音频结果。

扩展公共会话资源，使其支持用户范围的会话索引。需要提供会话分页列表、创建新会话、为已有会话签发新的 runtime、重命名、删除和按 owner 校验的历史查询。会话记录包含 owner、profile、创建来源（App 或 device）、标题、最近活动时间、角色版本快照和删除时间；轮次记录包含去重用的 turn/request 标识、文字转写、来源和时间，不保存原始音频。

Python runtime 每个完成轮次写入持久会话和现有短期运行时历史。设备链路使用同一写入服务归档设备轮次。重复事件按会话和 turn 标识幂等，迟到的设备事件不能覆盖较新的标题或时间。删除会话只隐藏并删除其文字历史，不触碰角色记忆。

### 共享记忆

记忆接口固定为 `/companion/profiles/{profileId}/memories`，支持列表、单条更新、单条删除和清空。所有入口统一检查角色归属和 `memoryEnabled`；关闭时列表返回 `enabled=false` 和空条目，写入、更新、删除和清空返回 `memory_disabled`，不删除已有内容。

底层建立稳定的角色记忆 namespace `companion:<userId>:<profileId>`，并保留硬件现有的按设备请求形状。硬件服务先解析设备 owner 和 active profile，再访问角色 namespace；App 直接访问角色 namespace。现有设备 namespace 与公共会话 namespace 作为 legacy 来源做一次性、可重试的合并迁移，记录来源和去重键，不能继续形成双写副本。迁移期间保留旧接口和回滚审计。

### 公共 WebSocket

保留现有文字和按次音频帧，并补齐移动端需要的续接和持续通话事件。持续通话沿用 `web.session.start`、PCM 二进制帧、`input.audio.commit`、`turn.cancel`/`response.cancel`、`stream.stop` 和心跳；服务端事件至少包括 `session.ready`、`stream.ready`、`asr.partial`、`asr.final`、`turn.started`、`llm.delta`、`tts.audio`、`turn.interrupted`、`turn.completed`、`error`、`session.expiring` 和 `session.expired`。续接已有会话时，runtime bundle 固定该会话保存的 profile version；新建会话才读取最新 active profile version。设备连接在每个新轮次边界重新解析 active profile，因此角色切换在下一轮生效，当前轮次不变。

## 音频与平台行为

单轮录音使用跨平台 PCM 流或临时文件，提交前由客户端生成 request ID，取消时直接丢弃临时数据。实时通话使用一个连接级状态机，禁止同时启动两个采集器或两个播放器。播放层只有一个队列，新的回复先停止旧项目；音频数据播放完成后释放临时 URL/文件。持续收音的后台能力由 Android 前台服务和 iOS `AVAudioSession`/后台音频能力共同提供，`audio_service` 只负责统一播放控制、系统通知和锁屏媒体事件。

Android 配置麦克风、前台音频服务、通知和网络权限；iOS 配置麦克风用途、后台音频模式、音频会话和通知类别。通话在锁屏或切后台时保持连接和音频会话，用户强制结束 App、权限被撤回或系统中断时进入暂停/结束状态，不伪造已完成轮次。通知动作只控制本地播放或结束连接，不重复提交消息。

WebView 仅允许访问设备本地地址和配网页面所需资源。Android 允许受限的明文本地访问，iOS 对设备局域网 HTTP 做最小 ATS 例外。页面导航拦截必须识别精确的设备地址和 `/done.html`，外部 URL 不自动放行。

## 错误与安全

所有 REST 响应先做协议校验，再更新状态。401 只触发一次 token 刷新并重放可重试请求，刷新失败回到登录。409 用于版本或绑定冲突，设备离线和设备命令失败分别显示可读状态。WebSocket 断线保留未发送草稿和已显示文字，重连前不重复发送上一轮；runtime 过期时为同一持久会话重新签发 token。

服务端始终做 owner、角色版本、能力授权和记忆开关校验。客户端不保存 provider URL、API key、MQTT 凭据、系统提示词之外的服务端秘密，也不把验证码、密码、原始音频、记忆全文写入普通日志。会话删除、清空记忆、解绑设备和角色删除都需要明确的二次确认。

## 测试与验收

Flutter 单元测试覆盖认证状态机、API 解码、角色版本切换、会话列表归并、记忆开关、VAD 分段、播放队列和配网导航拦截。Widget 测试覆盖认证页、双侧抽屉、角色编辑未保存保护、长按录音/上滑取消、全屏通话状态和设备向导。Android/iOS 集成测试覆盖真实权限、后台播放、锁屏通知、音频中断、WebView 回前台和系统 Wi-Fi 设置往返。

服务端 Java 测试覆盖 App 认证、联系方式唯一性、验证码风控、角色原子保存发布、软删除、会话 owner 校验、会话幂等写入和角色记忆接口。Python 测试覆盖持续 PCM、VAD 提交、打断、续接 runtime、TTS 二进制、断线清理和历史归档。现有硬件回归继续覆盖 MQTT 和设备记忆兼容接口。

真实验收按用户闭环执行：手机号和邮箱的密码/验证码登录、注册和找回；预设副本编辑与版本生效；文字、单轮语音和全屏通话的同一会话；打断、静音、锁屏和通知；App 与两个设备共享角色记忆；配网成功、热点断开、网页提交失败、设备离线和激活码错误；删除会话不删记忆；角色删除保护。Android 和 iOS 各至少完成一次真实设备或模拟器验收，记录版本、角色、会话和脱敏错误，不记录密码、验证码、音频或记忆全文。

## 非目标

首期不做订阅购买和权益运营，不做高级设备调试、固件升级、动态唤醒词和 Skill 编辑，不做 App 接管设备实时通话，不做用户原始录音云端存档，不做 Web 或桌面端。
