# 模型连接测试与对话参数说明设计

## 目标

模型管理页只在系统能够可靠验证连接时展示测试按钮，避免用户把不支持的探测误认为配置错误。对话模型的生成参数补充通俗说明、推荐值和有效范围，让用户知道数值调高或调低会发生什么。

## 连接测试

现有连接测试固定向配置地址追加 `/models`，并使用 Bearer 凭据发起请求。这只适合使用模型列表接口的 OpenAI 兼容对话模型和视觉模型。TTS 与 ASR 需要真实文本或音频请求才能确认功能，且不同供应器的接口、鉴权和输入格式不统一。VAD 通常是本地模型，不存在网络连接。Memory 供应器也没有统一的健康检查协议。因此，TTS、ASR、VAD、Memory 不展示测试连接按钮。

LLM 和 VLLM 只有在当前供应器为 `openai` 时展示测试连接按钮。其他供应器没有可靠探针时同样不展示。服务端继续保留连接测试接口，但在模型类型或供应器不受支持时返回明确的不可测试结果，防止旧客户端或直接调用继续触发误导性的网络请求。

前端组件测试覆盖各模型类型与供应器的按钮显隐。服务端单元测试覆盖受支持调用、非对话模型拒绝和非 OpenAI 供应器拒绝。

## 对话参数说明

说明只用于 LLM 的 `temperature`、`max_tokens`、`top_p`、`top_k` 和 `frequency_penalty` 字段。每个输入框下方显示一句用途说明，再说明调低、调高的变化和建议值。内容保持口语化，不要求用户理解采样算法。

温度推荐值为 `0.7`。数值低时回答更稳、更像固定答案；数值高时表达更多变，也更容易跑偏。最大令牌数推荐值为 `2048`。数值低时回答更短，过低会被截断；数值高时允许更长回答，也会增加等待时间和用量。top_p 推荐值为 `1`。数值低时只从更有把握的词里选择；数值高时表达更多样。通常只调整温度，不同时大幅修改 top_p。频率惩罚推荐值为 `0`。正值会减少同一词语反复出现，过高会让表达生硬。

top_k 没有跨供应器通用默认值。Google 等模型的默认值由具体模型决定，OpenAI 接口不原生支持该参数。界面不自动填入 top_k，提示常见起点为 `40`，只有供应器文档明确支持时才填写。运行时对显式填写的 top_k 通过兼容扩展字段传递；留空时完全不发送，避免破坏不支持该参数的 OpenAI 服务。

新建 OpenAI 对话模型时，温度、最大令牌数、top_p 和频率惩罚自动带入推荐值。编辑已有模型时尊重已保存值；缺失字段可以显示推荐值，但只有用户修改模型参数后才写回，避免无意改变旧配置。

## 数据与兼容性

参数说明和推荐值集中在前端的 LLM 参数元数据中，不修改所有历史供应器记录。字段渲染器接收模型类型，仅在 LLM 页面应用这些说明，避免 TTS 中同名的 temperature 或 top_p 被套用对话模型文案。

Python OpenAI 兼容运行时增加可选 top_k 读取。top_k 只在配置存在且为有效整数时加入 `extra_body`。其他四个参数沿用当前请求字段。无参数或旧配置的运行行为保持不变。

## 错误处理与验证

不支持测试的页面不出现按钮，因此不会再产生必然失败的提示。受支持测试仍沿用当前的超时、脱敏和简短错误信息。测试状态在表单变化后清空。

实现采用测试先行。前端先加入按钮显隐、说明文案和默认值的失败测试；Java 先加入模型类型与供应器能力判断的失败测试；Python 先加入 top_k 留空不发送、填写后通过扩展字段发送的失败测试。完成后运行相关单元测试、前端类型检查、前端构建和受影响的 Python 测试。

## 资料依据

OpenAI Chat Completions 文档把 temperature、top_p 和 frequency_penalty 定义为可选生成参数，其中 temperature 与 top_p 都用于控制随机性。Anthropic Messages 文档给出的 temperature 默认值为 `1.0`，并把 top_k 与 top_p 标为高级采样选项。Google Gemini 文档明确说明 temperature、topP、topK 和最大输出长度的默认值随模型变化。项目现有 OpenAI 兼容运行时已使用 temperature、max_tokens、top_p 和 frequency_penalty，示例配置采用 `0.7`、`500`、`1`、`0`。本设计采用更常见的通用输出上限 `2048`，同时在文案中提醒数值越高会带来更长响应。
