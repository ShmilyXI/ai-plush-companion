# 新版后台视觉优化设计

## 目标

将 `server/main/companion-console` 收敛为面向日常运营的紧凑工作台。首页优先展示设备健康和需要处理的事项，让用户进入后台后能快速判断系统是否正常，再进入设备、角色、记忆和管理页面处理具体任务。

本次只调整视觉和信息层级，不改变路由、权限、接口、数据结构、表单行为和现有业务边界。旧版 `manager-web` 不在本次范围内。

## 设计方向

整体采用浅灰侧栏、深墨色文字和单一蓝色操作色。页面背景使用冷灰白，内容表面使用白色，边框保持低对比但可辨识。蓝色只用于主按钮、当前导航、在线状态的强调和焦点环。移除大面积渐变、装饰性光晕和过重阴影。

后台使用紧凑密度。页面标题、说明、筛选、操作按钮保持稳定的行高；表格和设备行缩短垂直间距，但保留足够的触控高度。数字、版本号、时间和设备标识使用等宽数字，保证扫描时列对齐。

保留现有字体加载方式，不新增远程字体依赖。字体 token 将统一管理正文、标题和等宽数字的角色，中文回退到项目现有系统字体。

## 页面结构

`AppShell` 的侧栏继续承担主导航，按工作台、AI 能力和平台管理分组。浅灰侧栏在桌面端保持固定宽度，选中项使用浅蓝背景和深色文字；窄屏沿用 ProLayout 的折叠行为，不新增第二套移动导航。

首页保留在线设备、全部设备、陪伴角色和订阅状态四项摘要，但将它们作为轻量信息条而不是装饰卡片。摘要下方以不等宽布局展示最近设备和需要关注，最近设备占据主要宽度，需要关注使用窄面板呈现告警或缺失能力。最近会话保留为辅助面板，不与设备状态争夺首屏重点。

设备列表统一使用紧凑表格。设备名称、连接状态、硬件能力、版本和进入详情的动作保持固定列意图；整行可点击但不覆盖按钮和链接。空状态、加载态、错误态沿用现有语义，并使用相同的表面和间距 token。

管理员页面使用与普通页面相同的页面标题、告警、操作区和表格密度。`AdminPage` 只负责统一外壳，不改变各管理页的数据请求和操作逻辑。

## Token 设计

新增控制台内部 token 文件，并由全局样式和 Ant Design 主题共同引用。颜色 token 包含页面背景、表面、提升表面、正文、次要文字、边框、主操作、主操作文字、成功、警告、错误和焦点。间距采用 4 点基准，至少提供 `xs`、`sm`、`md`、`lg`、`xl` 五档。圆角控制在 6 到 10 像素范围，卡片和输入框不使用夸张的大圆角。

主题配置不再在 `AppThemeProvider.tsx` 和 `styles.css` 中重复维护同一组颜色。页面内新增颜色必须先进入 token 文件，再通过变量引用。

## 交互和可访问性

保留现有 Ant Design 控件和图标库。按钮、链接、表格行和菜单项提供明确的 hover、focus-visible、disabled 和 loading 状态，焦点环立即出现且不参与过渡动画。只对颜色、透明度和 transform 做短时过渡，不使用 `transition: all`。

根节点使用 `overflow-x: clip`，避免窄屏横向溢出。布局在 320、375、414、768 和桌面宽度下检查，点击文本保持单行，数据表只在必要时由表格容器横向滚动。

## 文件范围

预计修改 `server/main/companion-console/src/app/AppThemeProvider.tsx`、`server/main/companion-console/src/styles.css`、`server/main/companion-console/src/pages/DashboardPage.tsx`、`server/main/companion-console/src/pages/devices/DeviceListPage.tsx` 和 `server/main/companion-console/src/pages/admin/AdminPage.tsx`。

预计新增 `server/main/companion-console/src/tokens.css`，并在入口样式中引入。不会删除文件，也不会修改旧版 `manager-web`。

## 验证

继续运行控制台现有单元测试、lint、构建和 Playwright 质量测试。补充首页视觉检查，确认统计数据、设备错误态、空状态、管理员页面告警和窄屏布局没有回归。浏览器检查重点是首页、设备列表、设备详情和一个管理员表格页面。

## 非目标

本次不调整后台的信息架构，不合并旧版和新版代码，不重写认证，不引入新的组件库，不修改服务端 API，也不为首页编造业务指标。
