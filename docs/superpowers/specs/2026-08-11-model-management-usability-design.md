# 模型管理易用性调整设计

## 目标

改善模型配置和角色选模时的可见性，避免长表单遮挡测试结果，也避免未配置凭据的模型被角色选中。

## 交互设计

模型新增和编辑抽屉不再在表单顶部显示连接测试结果。底部的测试连接按钮承担状态展示：未测试时显示测试连接，测试中显示测试中，成功后显示测试成功和耗时，失败后显示测试失败。失败原因保留在按钮提示中。任意表单字段变化都会清除旧测试状态。

模型管理列表新增 Key 状态列。供应器没有凭据字段时显示无需配置；全部凭据字段已保存时显示已配置；其余情况显示未配置。状态由供应器字段定义和接口返回的已保存敏感字段路径共同计算，与编辑器的凭据识别口径保持一致。

语音合成 TTS 页签中的音色列使用固定宽度并禁止内容换行，避免表格布局变化时管理音色入口被挤压。

陪伴角色的 AI 模型下拉只列出已启用且凭据状态为已配置或无需配置的系统模型。若角色历史上已绑定一个当前不可用的模型，该模型仍作为不可选的当前值显示，并继续展示替换提示，避免表单值无故消失。

## 数据流

模型列表加载时同时取得当前模型类型的供应器字段定义。页面缓存每种模型类型的供应器数据，再根据模型供应器和已保存敏感字段路径计算 Key 状态。模型增删改或切换类型沿用现有列表刷新流程。

角色编辑继续使用现有模型选项接口。筛选只发生在下拉选项构造阶段，不改变历史绑定识别、告警和保存数据结构。

## 错误处理

连接测试失败不再占用抽屉顶部空间。按钮显示失败状态，悬停或聚焦时可查看服务端返回的简短失败原因。供应器元数据加载失败时沿用模型列表的错误提示，不展示可能错误的 Key 状态。

## 测试

组件测试覆盖连接测试状态只出现在按钮、Key 三态展示、TTS 音色列宽和角色下拉过滤。现有历史不可用模型告警测试继续保留。最后运行相关前端测试、类型检查和构建。
