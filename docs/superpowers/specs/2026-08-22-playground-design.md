# 操练场面板设计

## 目标

操练场是一个独立的虚拟设备实验室。用户可以从现有陪伴角色、模型、音色和技能目录中组合一份运行配置，在同一个虚拟会话里测试文字对话、语音对话、ASR、TTS、音色、视觉理解、活动感知、工具调用和记忆生成。操练场不占用真实设备连接，不修改角色草稿，不把测试历史写入服务端。

操练场历史只保存在当前浏览器的 `localStorage`。历史包含会话标题、创建时间、配置快照摘要、消息文本、结构化运行事件、模拟设备状态、记忆候选和记忆写入结果。音频输入输出只在当前页面内播放，不写入 `localStorage`；刷新后文字和测试结果仍在，音频需要重新试听。

## 架构

控制台新增受普通用户权限保护的 `/playground` 页面，并在工作台导航中提供入口。页面固定三栏。左侧显示浏览器本地会话索引；中间显示虚拟会话、消息、事件、音频和模拟设备屏幕；右侧显示当前配置和单项能力测试控制。

创建会话时，控制台提交陪伴角色、当前配置、模型引用、音色、技能、模拟设备尺寸和能力开关。`manager-api` 校验用户对这些资源的访问权，解析模型凭据和角色版本，生成一次不可变的虚拟会话快照，再向 Python 运行时建立虚拟设备上下文。浏览器后续发送的文本、语音、图片和活动感知输入都带上虚拟会话标识。Python 运行时按快照执行完整链路并返回结构化事件、音频结果和模拟屏幕状态。

```text
控制台
  │ 创建会话、发送输入、上传图片、提交活动状态
  ▼
manager-api
  │ 权限校验、目录解析、凭据解析、快照生成
  ▼
xiaozhi-server 虚拟运行上下文
  │ 文本/语音、ASR、LLM、TTS、视觉、活动、工具、记忆
  ▼
事件流、音频结果、模拟屏幕状态
```

虚拟会话状态只保留到会话结束或超时。操练场不会创建真实设备记录，不占用设备在线连接，不改变设备配置，也不直接写入正式设备记忆。临时记忆候选和写入结果属于操练会话；只有用户明确执行保存操作时，才调用既有记忆接口写入指定正式范围。模型密钥只在服务端内存中解析，浏览器只收到模型元数据、凭据状态和测试结果。

## 页面交互

固定三栏布局中，左栏提供新建会话、按最近时间排列的本地历史和删除当前历史的操作，并显示仅保存在当前浏览器的提示。点击历史后恢复文字消息、事件和配置摘要，不重新连接旧的服务端会话。

中栏显示当前会话标题、角色名和配置快照版本。消息支持文本发送和语音模式切换。语音模式使用浏览器麦克风采集并上传音频，服务端返回 ASR 事件和 TTS 音频。视觉理解通过图片上传触发，结果作为一条可展开的能力事件并注入后续对话上下文。模拟设备屏幕位于输入框上方，显示当前表情、状态、字幕或设备指令效果，并允许设置长、宽、高、屏幕方向和是否具备摄像头、麦克风等能力。活动感知使用静止、走动、摇晃等预设及可调参数提交模拟传感器事件。

右栏始终显示当前会话快照中的陪伴角色、LLM、ASR、TTS、VAD、Memory、音色、角色提示词、系统提示词、技能和模拟设备能力。配置下拉选项复用角色、模型、音色和技能目录接口。配置改变后标记为未应用，点击应用或新建会话才创建新的服务端快照，当前会话不会发生配置漂移。单项测试入口包括试听音色、ASR、TTS、视觉理解、活动感知和查看本次记忆。每个单项测试结果回写到中栏事件时间线，并保留重试按钮。

## 数据结构

浏览器使用版本化键 `xiaozhi.playground.v1`。根对象包含 `sessions`、`activeSessionId` 和 `updatedAt`。会话对象包含本地 `id`、标题、时间、`playgroundSessionId`、配置摘要、消息数组、事件数组、模拟设备状态和记忆结果。消息只保存角色、文本、时间、能力来源和可选的音频状态；事件保存能力类型、阶段、耗时、输入摘要、输出摘要、状态和错误信息；配置摘要不包含密钥值。

读取 `localStorage` 时校验版本和字段类型。数据损坏时保留可解析的会话并丢弃损坏项；旧版本通过显式迁移转换到当前结构。单个会话和全部历史都设置数量上限，超过上限时按最旧会话淘汰。音频 Blob 不写入本地历史。

## 服务端边界

沿用现有的角色、模型、音色、技能和能力目录查询接口。新增虚拟会话控制面，提供创建会话、获取会话快照、发送文本、上传语音、上传视觉输入、提交活动状态、订阅事件和结束会话的接口。事件接口采用现有控制台使用的 SSE 事件消费模式；音频通过短期结果地址或二进制响应返回，不进入日志和浏览器持久化历史。

创建会话必须绑定用户、角色和配置快照。服务端拒绝无权访问的角色、模型、音色和技能引用，拒绝浏览器提交的密钥字段，拒绝把未发布或不可用的技能加入可执行工具集合。Python 运行时上下文沿用现有连接级隔离约束，并将虚拟设备能力作为工具过滤输入。真实设备的能力、会话和记忆命名空间不会被虚拟会话复用。

## 失败处理

目录加载失败时保留上一次可用配置并显示具体错误。虚拟会话创建失败时不写入本地历史。ASR、TTS、视觉、活动感知或工具调用失败时只标记对应事件，主对话仍可继续。音频播放失败不改变服务端测试结果。事件流断开后，控制台按会话标识重连并补拉事件；超过重试次数后显示重新创建会话入口。

## 验收与测试

前端测试覆盖目录加载、配置快照隔离、`localStorage` 迁移和损坏恢复、三栏布局、文本与语音模式切换、模拟屏幕尺寸、图片上传、活动感知参数、单项测试重试、记忆候选展示、窄屏布局和键盘操作。服务端测试覆盖虚拟会话权限、快照不可变、凭据脱敏、设备能力过滤、事件顺序、断线重连和会话超时。集成测试验证一次完整虚拟链路能产生文本、ASR、LLM、TTS、视觉、活动和记忆事件，并确认不会写入真实设备或正式记忆。视觉验收覆盖桌面和窄屏的固定三栏布局、加载、空态、错误、禁用、焦点和文本溢出状态。

## 范围边界

首期只做虚拟设备操练，不驱动真实设备，不保存服务端操练历史，不提供多人共享会话，不持久化音频，不允许在操练场上传或执行任意代码。角色编辑器仍是正式配置的唯一保存入口；操练场只消费目录和快照，不替代角色发布、设备绑定或正式记忆管理。
