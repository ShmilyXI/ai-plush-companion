# 设备详情实时调试日志面板设计

## 目标

设备详情页增加一个可切换分类的调试日志面板，同时支持最近记录回看和实时事件追加。日志采集由设备级开关控制，默认关闭。开关关闭后不再保存新事件，已保存事件继续保留，直到超过 24 小时或单台设备超过 1000 条后自动淘汰。

这个面板只展示系统真实产生、能够按设备归属的数据。当前语音链路可以提供语音识别文本、AI 最终回复、模型处理阶段、工具调用与结果、音频处理阶段、连接状态、控制命令和异常。模型内部思考内容目前不可用。OpenAI 兼容运行时会关闭已知供应器的思考模式，并过滤 `<think>` 内容，因此界面不能把推测过程包装成思考日志。模型与工具页签会明确提示这一限制，只显示可观测的处理阶段、耗时和工具链。

## 页面结构

日志区放在设备详情页现有卡片区域底部，使用固定高度的独立卡片。卡片头部显示日志记录开关、实时连接状态、暂停自动滚动和清空当前视图。清空当前视图只清除浏览器中的当前列表，不删除服务端保留的记录。暂停自动滚动不会暂停接收事件，恢复后仍能看到暂停期间收到的内容。

面板包含全部、对话、模型与工具、音频链路、设备事件五个页签。全部按时间合并展示所有事件。对话展示 ASR 最终文本和 AI 最终回复。模型与工具展示模型请求开始、完成、失败、实际模型、耗时、工具名称、脱敏后的参数、结果和错误。音频链路展示 VAD、ASR、TTS 的关键开始、结束、耗时和异常，不记录原始音频帧。设备事件展示连接、断开、在线状态变化、采样后的心跳、设备控制命令和设备侧异常。心跳只记录状态变化和低频采样，避免周期消息挤掉更有用的调试事件。

首次打开日志区时，前端先加载当前设备最近 24 小时内的保留记录，再从最后一条事件的游标开始建立实时连接。历史和实时事件使用同一种展示模型，因此页签切换、级别样式、时间排序和详情展开行为保持一致。日志开关状态跟随设备详情返回，也可由日志卡片单独更新。

## 事件模型

每条事件包含唯一游标、设备编号、发生时间、服务端接收时间、会话编号、句子编号、分类、事件类型、级别、摘要、结构化详情和可选耗时。会话编号用于把一次连续对话串起来，句子编号用于关联 ASR、LLM、工具和 TTS。没有会话上下文的设备连接和控制命令仍可独立记录。

分类固定为 conversation、model_tool、audio 和 device。事件类型使用稳定名称，例如 asr.completed、llm.started、llm.completed、tool.called、tool.completed、tts.completed、connection.opened 和 command.failed。前端根据分类决定页签，根据事件类型决定标签和摘要，不解析自由文本日志。

结构化详情在写入前统一脱敏。字段名包含 key、token、secret、password、authorization 或 credential 的值不保存。系统提示词、完整模型上下文、服务密钥和原始音频不进入事件。ASR 文本、AI 回复和工具调试内容允许保存，但内容长度受限，超出部分截断并标记，防止单条事件占用过多空间。

## 开关与存储

`ai_device` 增加设备级调试日志开关字段，默认值为关闭。用户更新开关前必须通过现有设备归属校验。关闭开关只影响后续事件，既不删除 Redis 中的现有记录，也不改变原有聊天记录配置。

调试事件使用 Redis Stream 按设备保存。每台设备一个 Stream，追加时近似裁剪到 1000 条，并把键的有效期刷新为 24 小时。Redis Stream 的 ID 作为历史分页和实时续传游标。这个存储方式不新增长期数据库日志表，也适合多实例 manager-api 共享历史和实时消费。

manager-api 是开关的权威判断点。xiaozhi-server 和 manager-api 内部产生的候选事件都交给统一写入服务，写入服务先查询设备和开关，再决定是否追加到 Redis。这样开关变化立即生效，也不会依赖某条设备连接何时重新加载配置。关闭状态下候选事件不会成为日志记录。候选事件只覆盖对话和设备生命周期的关键节点，不发送音频帧、流式 token 或高频心跳。

## 服务间数据流

xiaozhi-server 增加一个不阻塞主链路的调试事件队列。ASR、LLM、工具、TTS 和连接处理代码只负责构造事件并放入队列，后台工作线程通过现有 manager-api 服务密钥把事件发送到新的内部上报接口。队列已满、网络失败或 manager-api 拒绝时丢弃调试事件并写本地错误日志，不能阻塞或中断语音对话。

manager-api 自身产生的设备控制命令和命令结果直接调用同一个事件写入服务。内部上报接口通过现有 ServerSecretFilter 鉴权，用户读取接口继续使用普通账号鉴权。写入服务根据设备编号或 MAC 地址解析真实设备，禁止上报方指定用户编号。

前端历史接口返回按时间升序排列的事件和最后游标。实时接口使用 SSE 格式输出事件，并接收最后游标用于续传。当前控制台通过 Authorization 请求头登录，原生 EventSource 无法可靠携带该请求头，因此前端使用 fetch 和 ReadableStream 读取 SSE，而不是把访问令牌放进 URL。连接断开后前端携带最后成功处理的游标重连，服务端先补发游标之后的保留事件，再继续等待新事件。重复游标在前端去重。

## 接口边界

设备详情响应增加 `debugLogEnabled`。用户接口提供开关更新、历史查询和实时流三个能力，路径挂在 `/companion/devices/{id}/debug-logs` 下。所有接口先执行现有的设备归属校验，不能通过角色编号或 MAC 地址绕开归属关系。

内部事件上报接口使用独立路径和服务密钥鉴权，只接受受控的分类、事件类型、级别和结构化字段。服务端重新生成接收时间并执行脱敏、截断和开关判断，不信任调用方传入的保留期限、用户信息或 Redis 键。

## 异常与状态

日志卡片区分正在连接、实时、重连中和已断开。历史加载失败时保留重试入口，不影响设备详情其他卡片。实时连接失败时继续显示已加载历史并自动重连。用户关闭记录开关后，实时连接可以保持，用于查看保留记录和接收开关状态变化，但服务端不会再出现新日志。

Redis 不可用、事件格式错误或内部上报失败都不能影响设备连接、语音识别、模型响应、语音合成和控制命令。相关失败只进入应用自身的普通服务日志。页面不展示伪造的成功事件，也不把客户端发起时间当成设备已经执行成功。

## 验证范围

manager-api 测试覆盖默认关闭、归属校验、开启后写入、关闭后停止新增、旧记录继续可读、24 小时过期、1000 条裁剪、游标续传、内部接口鉴权、脱敏和截断。xiaozhi-server 测试覆盖各关键节点的事件构造、后台上报失败不影响主流程、禁止上报原始音频和模型内部思考内容。前端测试覆盖日志开关、历史与实时合并、重复游标去重、断线续传、暂停滚动、清空当前视图、五个页签分类、连接状态和思考过程不可用提示。

完成实现后运行 companion-console 的相关组件测试、类型检查和构建，运行 manager-api 的相关单元与集成测试，并运行 xiaozhi-server 的调试事件与受影响语音链路测试。
