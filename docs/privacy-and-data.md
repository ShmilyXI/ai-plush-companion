# 用户数据和隐私

本文记录网页端保存了用户的哪些数据、用户能对自己的数据做什么，以及对外开放前还必须处理的事项。面向用户的说明在 `companion-web` 的 `/privacy` 和 `/terms` 两个页面里。

## 保存了什么

| 数据 | 位置 | 说明 |
|---|---|---|
| 手机号 | `sys_user` | 登录凭据 |
| 登录会话 | `app_user_token` | 令牌的哈希、设备类型、登录时的网络地址 |
| 对话文字 | `ai_conversation_turn` | 用户说的话和角色的回复，按“用户 + 角色”保存 |
| 对话用量 | `ai_conversation_usage` | 轮数、字数、耗时、模型，不含内容 |
| 安全事件 | `ai_safety_event` | 类别和处理方式，不含内容 |
| 邀请码使用记录 | `ai_invite_code_use` | 哪个账号用了哪个邀请码 |
| 协议同意记录 | `ai_user_consent` | 同意的协议版本和时间 |
| 客户端事件 | `ai_client_event` | 事件名和少量属性，例如麦克风打开失败，不含内容 |

网页对话不保存用户的录音，也不保存用户发送的图片。录音只在识别成文字时使用，图片只用于生成当次回复。

## 录音默认不保存

设备对话有一个“聊天记录配置”，可以选择不记录、只记录文字、文字和录音都记录。之前在没有明确设置时默认是文字和录音都记录，这和产品约定的“长期只保存文字转写，不保存用户原始录音”相反。

现在没有明确设置时只记录文字。保存录音必须是有人明确打开的。已经明确设置为记录录音的角色不受影响。

## 用户同意

登录页要求用户勾选“我已满 18 周岁，并已阅读和同意《用户协议》和《隐私政策》”才能登录。

协议有一个版本号，在 `companion-web/lib/consent.ts` 里。登录时版本号随请求交给 manager-api，按“用户 + 版本”记一次同意。协议有实质变化时改版本号，用户下次登录会重新确认。

## 用户能做什么

对话页右上角的“设置”里有三件事。

**清空对话记录。** 删除自己和某个角色的全部对话记录。清空后页面上的消息一并清掉，并换一个新会话，角色从空白开始。

**注销账号。** 注销不可恢复，所以除了已登录之外，还要再用一次发到账号手机号上的短信验证码确认是本人。验证通过后：

- 删除：账号、角色、设备绑定、对话记录、登录会话、邀请码使用记录、协议同意记录、客户端事件、账号级模型凭据、个人模型、订阅、API Key、音色克隆、屏幕场景。
- 改为匿名：对话用量和安全事件。这两类记录只有数量和类别，没有内容，把用户改成 0 之后不再对应到任何人，同时不影响整体统计。

管理员账号不能从这个入口注销。

**退出登录。** 通知服务端作废当前会话，并清掉浏览器里的登录状态。

## 对外开放前必须处理

这些事项不是代码能单独解决的，需要运营主体和法务决定。

1. **协议是草案。** `/privacy` 和 `/terms` 是按系统实际的数据处理方式写的草案，运营主体名称、联系方式和服务商清单都留着方括号，全文需要法务审定。
2. **语音合成的数据出境。** 默认的语音合成是微软的 Edge 语音合成，角色回复的文字会发送到境外的服务器。对外开放前要么换成境内的语音合成服务，要么按数据出境的要求处理并在隐私政策里写明。
3. **大模型服务商。** 对话文字会发送给配置的大模型服务商。服务商是谁、数据存放在哪里、是否用于训练，需要逐个确认并写进隐私政策。
4. **保存期限。** 对话记录目前没有自动过期，只能由用户主动删除。是否需要设置期限由法务决定。
5. **对话记录是明文保存的。** 数据库的访问控制、备份的保护和是否加密需要在部署方案里确定。
6. **未成年人。** 目前只有登录时的自我确认和提示词里的一条规则，没有任何识别手段。
7. **外部记忆服务。** 默认不使用记忆模块。如果启用了把内容存到外部服务的记忆模块，注销账号时还需要同步删除那边的数据，目前没有处理。
8. **查询、更正和导出。** 用户想导出自己的数据时，目前只能联系运营处理，没有自助入口。
