# 网页端在手机上的表现

`companion-web` 同一套页面同时服务电脑和手机浏览器，包括微信内置浏览器。本文记录为手机做的处理，以及哪些还没有在真机上验证。

## 布局

样式先按手机写，屏幕宽度达到 720px 后再放宽。

对话页占满整个可视高度：顶部是角色名和连接状态，中间的消息区单独滚动，输入栏贴在底部。高度用 `100dvh`，手机地址栏收起和键盘弹出时会跟着变化。页面延伸到刘海和底部横条下面，四周用 `env(safe-area-inset-*)` 留出边距。

新消息到来时消息区滚到底部。用户自己往上翻看时不会被拽回去，翻回底部附近后恢复跟随。

输入框和下拉框的字号是 16px。小于这个字号时，iOS 会在聚焦输入框时自动放大整个页面。页面没有禁用缩放。

按钮和输入控件的高度不小于 44px。

## 语音回复的自动播放

手机浏览器不允许页面自己开始播放声音。角色的语音是在用户点了发送之后几秒才到的，那时再新建 `<audio>` 去播放会被拦截。

页面用一个共享的 `AudioContext` 播放语音回复，在用户第一次触摸或按键时解锁，之后到达的语音都通过它依次播放。实现在 `lib/playback.ts`。

没有解锁成功、浏览器不支持或者格式解码失败时，退回到逐个 `<audio>` 元素播放。每条回复下面也保留了播放控件，自动播放不成功时可以手动点。

用户开口打断时停止播放，并把已经播放了多少毫秒告诉服务端。

## 麦克风

浏览器只在 HTTPS 或本机地址下提供麦克风。用局域网的 `http://` 地址在手机上打开时拿不到麦克风，页面会提示改用 HTTPS，文字对话不受影响。

麦克风被拒绝、被占用或者不存在时，各有对应的中文提示。

录音用 `ScriptProcessorNode` 取样，在浏览器里降到 16 kHz 单声道后发给服务端。

## 输入

手机键盘的回车键显示为“发送”。中文输入法正在选词时按回车不会发送。

连接中断、正在重连时仍然可以输入，见 `docs/conversation-continuity.md`。

## 验证情况

已经验证的：在桌面浏览器里用 375×812 和 1280×800 两种尺寸检查过布局，没有横向溢出，页面本身不滚动，输入栏贴底。

还没有验证的：

- iOS Safari、微信内置浏览器、Android Chrome 真机上的自动播放和麦克风。
- 键盘弹出时输入栏的位置。
- 蓝牙耳机和听筒、扬声器之间的切换。

真机验证需要 HTTPS。除了页面本身，浏览器到 `zixuan-server` 的实时连接也必须是 `wss://`，因为 HTTPS 页面不能打开 `ws://` 连接。本机开发环境目前两者都是明文，所以只能在电脑上验证语音。
