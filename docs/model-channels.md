# 模型连接

管理台“模型管理”里的对话类模型按三层管理：连接、模型、默认模型。本文记录这三层在服务端的含义和约束。

## 三层的含义

连接是一家服务商的接口地址和密钥，对应 `ai_model_channel` 表。一个账号只需要建一个连接。

模型是连接下的一个具体模型，仍然是 `ai_model_config` 表里的一行，用 `channel_id` 指向所属连接。服务商给出的模型代号保存在 `config_json.model_name`，温度、最大输出长度等参数也保存在这一行的 `config_json` 里。

默认模型沿用原有的 `is_default` 字段。每种用途有一个默认模型，角色可以在自己的设置里另外指定。

## 一个模型只导入一次

管理台上一个模型只占一行，带“对话、视觉、向量”三种能力的勾选。导入时不需要先选类型：管理台按模型代号识别能力，例如能看图的对话模型同时勾上对话和视觉，识别得不对可以在模型列表里直接修改。在“默认模型”里也可以把一个已导入的模型直接指定给它还没有勾选的用途，管理台会先补上这种能力再设为默认。

服务端仍然按用途各存一行 `ai_model_config`，因为角色、配置下发和运行时都是按用途引用模型的。管理台按“连接 + 模型代号”把这些行合并显示，勾选一种能力就是新建对应用途的那一行，取消勾选就是删除那一行。同一个模型的几行共用显示名称和启用状态，参数按用途分别保存。

向量模型不能用对话模型代替，所以向量的默认模型只能从勾选了向量能力的模型里选。

## 适用范围

连接目前只管理对话类模型，即对话（LLM）、视觉（VLLM）和向量（Embedding），接口协议支持 OpenAI 兼容和 Ollama。Ollama 连接只能添加对话模型。

语音识别、语音合成、语音活动检测和记忆模型没有统一的模型列表接口，各家的凭据格式也不同，仍然在“全部模型配置”里逐个配置。Coze、Dify、FastGPT 这类接入的是一个应用而不是一组模型，同样逐个配置。

`channel_id` 为空的对话模型是连接出现之前的旧配置，行为不变。

## 地址和密钥只有一个来源

连接是接口地址和密钥的唯一来源。添加模型和修改连接时，管理服务把连接的协议、地址和密钥写入该连接下每个模型的 `config_json`，并清掉这些模型的缓存。配置下发、连接测试、角色生效模型解析等所有读取 `config_json` 的地方因此不需要知道连接的存在，`zixuan-server` 也不需要改动。

为了保证这一点：

- 通过旧的模型编辑接口修改挂在连接下的模型时，`type`、`base_url` 和 `api_key` 始终保留原值。
- 连接下还有模型时不能删除连接。
- 连接的接口协议创建后不能修改。

OpenAI 兼容连接没有填密钥时，模型配置里写入占位值 `EMPTY`，因为运行时的 OpenAI 客户端要求密钥非空。

## 密钥的保存和传输

连接的密钥用 `server.secret` 加密后保存在 `ai_model_channel.secret_config_ciphertext`。接口只返回是否已配置，从不返回密钥内容；修改连接时密钥留空表示保留原值。

拉取模型列表和测试连接由管理服务向服务商发起请求，密钥不经过浏览器。失败时返回的消息只包含 HTTP 状态和处理建议，不包含密钥和服务商返回的正文。

## 接口

接口在 `/model-channels` 下，全部需要超级管理员权限。

| 接口 | 作用 |
|---|---|
| `GET /model-channels` | 连接列表 |
| `POST /model-channels` | 新增连接 |
| `PUT /model-channels/{id}` | 修改连接，并同步到连接下的模型 |
| `DELETE /model-channels/{id}` | 删除没有模型的连接 |
| `POST /model-channels/test`、`POST /model-channels/{id}/test` | 测试未保存或已保存的连接 |
| `GET /model-channels/{id}/upstream-models` | 从服务商拉取模型列表 |
| `GET /model-channels/models` | 所有连接下的模型 |
| `POST /model-channels/{id}/models` | 把模型添加到连接下，已添加过的同用途模型会跳过 |
| `PUT /model-channels/models/{modelId}` | 修改模型的显示名称和参数 |

启用、设为默认和删除模型继续使用 `/models` 下的原有接口。

模型参数只能修改该协议在 `ai_model_provider` 里声明的字段，`type`、`base_url`、`api_key` 和 `model_name` 不能当作参数修改。

## 与账号级凭据的关系

`ai_companion_global_model_credential` 保存的是用户给某个系统模型填的自己的密钥。连接保存的是平台自己的密钥，写入系统模型的 `config_json`。

挂在连接下的模型由平台提供密钥，对所有用户可用：

- 没有厂商元数据时，这类模型的凭据要求按“无需配置”处理，所以在角色的模型选择里可以直接选。
- 用户不能给这类模型另外填地址、模型代号或密钥，对应的保存和测试接口会拒绝。
- 运行时解析这类模型时不读取用户的账号级凭据。

## 平台密钥只发往平台配置的地址

只要解析出来的配置里带的是平台自己的密钥，用户能控制的输入就不能改变请求发往哪里、带什么凭据。这包括两种情况：挂在连接下的模型，以及用户没有填自己的密钥、回退到系统模型自带密钥的旧配置。

这两种情况下，`CompanionEffectiveModelServiceImpl` 不应用用户填的接口地址，并丢弃角色模型覆盖项里的以下配置：`type`，名字里带 `url`、`uri`、`host`、`proxy`、`endpoint`、`address` 的地址类配置，以及密钥类配置。温度、最大输出长度等参数类覆盖项不受影响。

用户使用自己的密钥时不受这条限制，仍然可以指定自己的接口地址。
